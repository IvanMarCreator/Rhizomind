# Словарь Rhizomind

Единые термины для кода, документов и интерфейса. Новый термин сначала добавляется сюда.

## Хранилище и файлы

| Термин | English | Значение |
|---|---|---|
| Хранилище | Vault | Папка на диске с заметками. В окне открыто одно хранилище. |
| Контур хранилища | Vault boundary | Граница, за которую приложение не читает и не пишет. |
| Служебная папка | `.rhizomind` | Технические данные хранилища: настройки, индекс, раскладка, темы, журнал. Скрыта в дереве файлов. |
| Список хранилищ | Vault registry | Единственный файл в профиле ОС: имена и пути хранилищ, последнее открытое, размер окна. |
| Заметка | Note | `.md`-файл внутри хранилища. |
| Вложение | Attachment | Не-Markdown файл в хранилище: картинка, PDF и т.п. |
| Правило вложений | Attachment rule | Настройка: в какую папку хранилища сохранять файлы определённого типа. |
| Слежение за папкой | Vault watcher | Получение уведомлений ОС об изменениях файлов хранилища, пока приложение открыто. |
| Полная сверка | Rescan | Наблюдатель заново сравнивает всё хранилище с диском (переполнение буфера ОС, хранилище снова доступно). Окно перечитывает дерево и сверяет открытые заметки с диском. |
| Внешнее изменение | External change | Изменение файла хранилища, сделанное не Rhizomind (другой редактор, Git, восстановление из корзины). |
| Версия файла | File version | Дата изменения, размер и хэш содержимого файла. По ней ядро отличает свои записи от внешних и обнаруживает конфликт. |
| Конфликт изменений | Change conflict | Файл открытой заметки изменился снаружи, а в редакторе есть несохранённые правки. Сохраняются обе версии: версия с диска — копией рядом. |
| Путь в хранилище | Vault path | Путь от корня хранилища по компонентам: `["Проекты", "Встреча.md"]`; корень — пустой список. Так пути передаются между интерфейсом и ядром: из строки не разбираются. |
| Ключ имени | Name key | Имя после NFC → приведения регистра → NFC. Имена совпадают для ядра, если совпадают ключи: дубликаты в папке, разрешение ссылок, поиск. |

## Ссылки и метаданные

| Термин | English | Значение |
|---|---|---|
| Вики-ссылка | Wikilink | `[[цель]]`, `[[цель\|псевдоним]]`, `[[цель#заголовок]]`. |
| Псевдоним | Alias | Отображаемый текст ссылки после `\|`, например для падежей. |
| Встраивание | Embed | `![[файл]]`: показ файла или заметки внутри заметки. |
| Кратчайший различающий путь | Shortest unique path | Путь в ссылке на заметку с повторяющимся именем: столько папок с конца пути, сколько нужно для однозначности. `[[Альфа/Встреча]]`. |
| Неразрешённая ссылка | Unresolved link | Ссылка на заметку, которой нет. Клик создаёт заметку. |
| Обратная ссылка | Backlink | Ссылка из другой заметки на текущую (и сама ссылающаяся заметка). Ссылка заметки на себя — не обратная; ссылка на заголовок и встраивание `![[…]]` — обратные. Ссылки в коде и в свойствах не считаются. |
| Тег | Tag | `#тег` в тексте или значение `tags`/`tag` в свойствах. Теги **плоские**: подтегов и вложенности нет, каждый тег — отдельная сущность; `_`, `-` и `/` — часть имени (`#работа/отчёт` — самостоятельный тег, не связан с `#работа`). `#` + только цифры — не тег. |
| Ключ тега | Tag key | Тег после NFC → приведения регистра → NFC, как ключ имени: `#Проект` и `#проект` — один тег. Показывается самое частое написание. |
| Свойства | Properties / frontmatter | Блок `---` в начале заметки. В 1.0 только чтение тегов. |
| Индекс | Index | Индекс хранилища: вычисляемые данные о содержимом заметок (заголовки, теги, ссылки с положениями) в `.rhizomind/index.json`; по нему — обратные ссылки и теги. Текста заметок в нём нет. Пока строится, обратные ссылки, теги и обновление ссылок ждут. |
| Список заметок | Note list | Пути и даты создания всех заметок хранилища: по нему разрешаются ссылки и работает быстрый переход. Не индекс: о содержимом заметок не знает. |
| Обновление ссылок | Link update | Переписывание ссылок в заметках после переименования или перемещения по правилу «ссылка ведёт туда же»: меняется только цель ссылки и только там, где иначе ссылка сломалась бы или повела бы на другую заметку. Заголовок и псевдоним остаются. |
| Уточнение ссылки | Link clarification | Переписывание ссылки на кратчайший различающий путь, когда появилась заметка с тем же именем и ссылка стала бы неоднозначной. Не зависит от настройки обновления ссылок; обратно не упрощается. |
| План переписывания | Relink plan | Посчитанный ядром список «заметка → какие ссылки на какую цель переписать». Интерфейс видит только число заметок и ссылок и может план подтвердить или отклонить, но не составить. |
| Знак плана | Relink token | Непрозрачный знак, которым ядро отдаёт интерфейсу план переписывания: случайный, одноразовый, привязан к окну и к плану, живёт 600 с. По знаку интерфейс может только подтвердить или отклонить план ядра, но не назвать свои файлы. |
| Подтверждённое переименование | Confirmed rename | Переименование или перемещение на диске, в котором наблюдатель узнал тот же файл под новым именем (тот же идентификатор файла и дата создания). «Удалили и создали заново» — не переименование: ссылки не обновляются. |
| Шаблон | Template | Готовая заметка в папке шаблонов, копируется при создании новой. |
| Папка шаблонов | Templates folder | Обычная папка, отмеченная в настройках хранилища. |

## Интерфейс

| Термин | English | Значение |
|---|---|---|
| Живой предпросмотр | Live preview | Режим редактора: разметка прячется, пока курсор не в ней. |
| Режим исходного текста | Source mode | Режим редактора: разметка видна целиком, без форматирования. Переключается кнопкой и горячей клавишей. |
| Быстрый переход | Quick switcher | Окно по Ctrl+O: переход к заметке по части названия. |
| История переходов | Navigation history | Переходы «назад» и «вперёд» между открытыми заметками. |
| Командная палитра | Command palette | Окно действий по горячей клавише. |
| Раскладка | Workspace layout | Деление окна на панели и вкладки. |
| Панель | Pane | Область окна с одним или несколькими видами (заметка, обратные ссылки, граф). |
| Граф | Graph | Визуализация заметок и связей. |
| Цветовая группа | Color group | Правило графа: узлы по тегу, папке или запросу получают цвет. |
| Тема | Theme | Набор значений переменных темы. Встроенные — тёмная и светлая; свои — CSS-файлы в `.rhizomind/themes`. |
| Переменные темы | Theme tokens | CSS-переменные, через которые задаются все цвета интерфейса. |
| Словарь интерфейса | UI strings | Все тексты интерфейса по ключам; один словарь на язык. |
| Лента иконок | Ribbon | Узкая полоса значков у левого края окна: «Файлы», «Быстрый переход», внизу «Настройки». |
| Боковая панель | Sidebar | Область слева от заметки: дерево файлов, внизу переключатель хранилищ. |
| Дерево файлов | File tree | Все папки и файлы хранилища в боковой панели: папки сверху, естественный порядок; создание, переименование, перемещение перетаскиванием, удаление в корзину. Скрытые (с точкой в начале) не показываются. |
| Строка над заметкой | Note header | Полоса над текстом заметки: «назад/вперёд», путь, переключатель режима «книга/карандаш». |
| Переключатель хранилищ | Vault switcher | Пункт внизу боковой панели: список хранилищ и «Управление хранилищами…». |
| Окно «Управление хранилищами» | Vault manager | Отдельное окно без хранилища, одно на программу: список хранилищ, «Создать хранилище», «Открыть папку как хранилище», «Убрать из списка». При первом запуске служит окном приветствия. |
| Окно «Настройки хранилища» | Vault settings | Модальное окно по шестерёнке на ленте: разделы «Общие», «Редактор», «Файлы и ссылки», «Оформление», «Горячие клавиши», «О программе»; всё хранится в `.rhizomind/settings.json` хранилища. |
| Команда интерфейса | UI command | Действие из реестра горячих клавиш (`src/settings/hotkeys.ts`): быстрый переход, новая заметка, режим заметки, назад/вперёд, переименовать, удалить. У команды — сочетания по умолчанию и назначения пользователя. |
| Сочетание клавиш | Key chord | Модификаторы и физическая клавиша (`Ctrl+KeyO`): работает в любой раскладке. Системные сочетания (Ctrl+C/V/X/Z/Y, Alt+F4) не переназначаются. |
| Уведомление | Notice | Короткое сообщение внизу окна, исчезает само. |
| Пустое состояние | Empty state | Вид области заметки, когда ни одна заметка не открыта. |

## Продукт и безопасность

| Термин | English | Значение |
|---|---|---|
| Редакция | Edition | Secure, Community или Server. |
| Выпуск | Release | Версия 0.x, пригодная для ежедневной работы. План — в `docs/product/requirements.md`. |
| API ядра | Core API | Узкий версионированный набор действий, которые интерфейс вызывает у ядра. Будущая граница для плагинов Community. |
| Сетевой выключатель | Network lockdown | Механизмы, которые доказывают отсутствие сетевых запросов. |
| Временная папка WebView2 | WebView2 data folder | Папка данных браузерного движка во временном каталоге ОС (`rhizomind-<случайное>`): служебные файлы, которые движок не может не создавать. Удаляется после завершения процесса браузера. |
| Системная версия WebView2 | Evergreen WebView2 | WebView2, установленный в Windows и обновляемый Microsoft или службой ИТ. Используется Rhizomind. |
| Встроенная версия WebView2 | Fixed version WebView2 | Фиксированная копия WebView2 в папке приложения, обновляемая вместе с приложением. Не используется; описана в `SECURITY.md` как способ отказаться от обращений WebView2 к Microsoft. |
| Команда ядра | Core command (Tauri command) | Функция ядра на Rust, которую интерфейс может вызвать. Набор команд ядра и их событий и есть API ядра. |
| Разрешение | Capability / permission | Явная запись о том, какие команды ядра и права плагинов доступны окну. Чего нет в разрешениях, интерфейс вызвать не может. |
| Версия API | API version | Номер версии API ядра (сейчас 1). Ядро возвращает его командой `vault_current`, интерфейс сверяет при запуске. |
| Снимок контракта | Contract snapshot | Файл `contracts/v1/<команда>.snap` с примером запроса, ответа и ошибок команды ядра (или данных события). Его пишет `cargo test`, а тесты интерфейса сверяют со своими типами. |
