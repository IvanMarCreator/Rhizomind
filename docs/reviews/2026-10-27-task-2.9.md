# Задача 2.9 «Внешние изменения в редакторе» — что сделано и что отложено (27.10.2026)

Ветка `task/2.9-external-changes` от main a8a98bb. Критерий готовности из плана: «сценарные тесты на Windows для каждого случая С3.6; ни в одном не теряется текст» (инвариант 4, критерий приёмки С9.7). Решение владельца 70: последняя задача волны до КТ2.

Ядро к задаче уже было готово (задачи 1.4, 1.7, 2.12): наблюдатель, журнал своих записей `src-tauri/src/own_writes.rs`, конфликт при записи с копией «Имя (внешняя версия ГГГГ-ММ-ДД ЧЧ-ММ).md» (`Vault::write_note`), события `note:changed`, `note:renamed`, `note:deleted`, заголовок окна за переименованием (`follow_shown`). Интерфейс этих событий не слушал — это и закрывает задача. **Ядро и контракт API не менялись.**

## Не сделано и почему

| Пункт | Почему | Куда |
|---|---|---|
| Перенос, совпавший с правкой за одну склейку событий (~0,5 с), выглядит как «исчез + появился»: открытая заметка закрывается как удалённая, последняя секунда ввода отбрасывается (файл цел под новым именем) | Так устроено распознавание переименований в ядре (ADR 0006: тот же идентификатор с другим содержимым — не переименование, защита от повторно выданного inode); менять наблюдатель — отдельная задача ядра | Решение владельца 89 (Б: тот же файл — переименование); реализация — задача ядра 1.9 |
| Отдельный сценарий «правка снаружи при конце сеанса Windows» | Конец сеанса идёт тем же `flushForClose`, что закрытие окна (сценарий есть); сценарий конца сеанса (`session-end.test.ts`) проверяет сам механизм | — |
| Событие ядра `note:conflict-saved` интерфейс не слушает | Тот же факт приходит ответом `note_write` (`conflict_saved`), уведомление показывается по нему; слушать оба — двойное уведомление | — |

## Сомнения

- **Курсор «по возможности».** Если правка снаружи задела строку с курсором, курсор встаёт на край изменённого куска. Прокрутка не трогается.
- **WebKitWebDriver теряет повтор одинаковых клавиш подряд** («вв» → «в», `['ArrowDown','ArrowDown']` → одна): в сценарном тесте клавиши по одной и текст без двойных букв. Похоже на ограничение драйвера, не приложения; на Windows (msedgedriver) не наблюдалось в других тестах.
