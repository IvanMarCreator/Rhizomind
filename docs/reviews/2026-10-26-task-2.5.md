# Задача 2.5 «Редактор, шаг 2: живой предпросмотр и режим исходного текста» — отчёт разработчика (26.10.2026)

Ветка `task/2.5-live-preview` от main 51d52a5. Ревью кода и безопасности — за другими агентами (раздел «Что проверить на ревью»).

## Сделано
- `src/editor/live-preview/markdown.ts` — свой построчный разбор Markdown для оформления (С3.3): заголовки ATX 1–6, `**`/`__`, `*`/`_`, `~~`, код в строке, ссылки `[текст](адрес "заголовок")`, цитаты (вложенные), списки `-`/`*`/`+`/`1.`/`1)`, чекбоксы, линия `---`/`***`/`___`; блоки кода с оградой и блок свойств — `scanBlocks`. Выделение — алгоритм CommonMark «process emphasis» (фланкирование, правила для `_`, «кратно трём»).
- `src/editor/live-preview/index.ts` — расширение CodeMirror: оформление по видимой части (`ViewPlugin`), блоки кода в `StateField` (набор диапазонов сдвигается за правкой; полный пересчёт — только если правка задела строку-ограду или блок свойств), значки (точка списка, чекбокс, линия), щелчки по чекбоксу и ссылке.
- `src/editor/codemirror.ts` — режим в `Compartment` (`setMode`): переключение меняет только набор расширений, документ и выделение те же. Режим исходного текста — без расширения: разметка как есть, без оформления.
- Переключатель «книга / карандаш» (`src/shell/NoteHeader.svelte`) по Э13: `radiogroup`, одна остановка Tab, ← / →, кольцо фокуса 2 px, наведение `bg/active`, подсказка «Режим [Ctrl]+[E]» через 0,5 с наведения или сразу при фокусе с клавиатуры; для заметки только для чтения — «… — только просмотр». Ctrl+E — `src/editor/live-preview/keys.ts` (по `code`, работает в русской раскладке), обработчик в `Shell.svelte` (под модальным окном не действует).
- Запоминание: `WindowModel.setEditorMode` (`src/shell/window.svelte.ts`) — режим сразу в окне, запись в настройки хранилища: `settings_read` → `settings_write` с новым `editor_mode`, записи по очереди. Контракт v1 не менялся: поле `editor_mode` уже было.
- Внешние ссылки: `openLink` в `Editor.svelte` — только `core.openExternal`; ошибка — уведомление, отмена — тишина.

## Отступления и решения разработчика
1. **Без `@lezer/markdown` / `@codemirror/language`.** Реестр npm из облачной среды недоступен (DNS), поэтому новые пакеты не ставились; разбор написан сам. Плюс для ИБ: новых зависимостей, лицензий и исключений проверки сети нет (`check:network` — 9 прежних исключений). Минус: упрощения ниже. Если владелец/оркестратор захочет полный CommonMark — заменить `markdown.ts` на `@lezer/markdown` можно, не трогая оформление (интерфейс `parseLine`/`scanBlocks`).
2. Не оформляются (исходный текст, «всё, чего нет, — исходный текст», раздел 1 спецификации): setext-заголовки (`---` под текстом не линия), код отступом 4 пробела, ограды внутри цитат и списков, выделение через перенос строки, картинки (0.3), HTML, блок свойств (0.2), строки > 10 000 символов (защита от O(n²)).
3. Строка с курсором: разметка видна приглушённо (`text/faint`), оформление (жирный, заголовок) остаётся. Чекбокс на строке с курсором — текст `[ ]`; щелчок по чекбоксу на другой строке не переносит курсор.
4. Ссылка на строке с курсором — текст для правки, открывается Ctrl+щелчком. В режиме исходного текста ссылки не открываются (для вики-ссылок С3.4 Ctrl+щелчок — задача 2.6 может добавить и для `[](…)`).
5. Нумерованный список: номер не прячется (это содержание), а приглушается.
6. Режим по умолчанию до чтения настроек — живой предпросмотр (как было в `WindowModel`).

## Замер (10 МБ плотного Markdown, Node)
Создание состояния — ~0,6 с (исходный текст — ~0,2 с), правка обычной строки — ~0,3 мс, оформление видимой части — ~2 мс. Правка строки, похожей на ограду, пересчитывает блоки всего текста (~0,4 с на 10 МБ) — для больших заметок с частыми оградами можно пересчитывать с места правки; пока не нужно.
