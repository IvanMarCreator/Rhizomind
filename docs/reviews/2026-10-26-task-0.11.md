# Задача 0.11: сохранение ввода при выходе из системы и выключении Windows

Ветка `task/0.11-shutdown-save`. Снимает ограничение W1 из ревью 0.7 (`docs/reviews/2026-10-26-task-0.7.md`): tao 0.37.2 не обрабатывает `WM_QUERYENDSESSION`, а на `WM_ENDSESSION` своего скрытого окна сразу вызывает `std::process::exit(0)` (`tao-0.37.2/src/platform_impl/windows/event_loop.rs`, `thread_event_target_callback`, ~2338–2351). `CloseRequested` не приходит — несохранённый ввод терялся (инвариант 4).

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Сабклассинг окна tao (`SetWindowSubclass` на окне класса `Tao Thread Event Target`) | `WM_ENDSESSION` перехватывается до `exit(0)` | Окно ищется по внутреннему имени класса tao (`EnumThreadWindows`): сломается при обновлении tao молча; нужна функция `Win32_UI_Shell` с comctl32 |
| **Б. Своё скрытое окно верхнего уровня** (выбрано) | Не зависит от внутренностей tao; тот же приём, что окно одного экземпляра (0.5) | Порядок `WM_ENDSESSION` между нашим окном и окном tao не задан — поэтому вся запись делается на этапе `WM_QUERYENDSESSION`, а завершение браузера продублировано в `RunEvent::Exit` |
| В. Патч tao (своя копия, как wry) | Правильное место | Ещё одна своя копия зависимости; обновления tao — вручную |

Окно «только для сообщений» (`HWND_MESSAGE`) не подходит: Windows рассылает `WM_QUERYENDSESSION` окнам верхнего уровня.

## Что сделано

- `src-tauri/src/session_end/mod.rs` — логика без ОС: `save_all` (каждому окну хранилища — `window:close-requested`, ожидание ответов через `Closing` из 0.7 без скрытия и уничтожения окон, разбор очереди сообщений в ожидании, предел `SESSION_END_TIMEOUT` = 4 с; окно, уже закрывающееся пользователем, ждётся по своему циклу; вложенный запрос не повторяет запись), `on_end_session` (признак выхода, завершение браузера; `FALSE` — отмена), `end_browser_if_ending` (браузер завершается один раз — из нашего окна или из `RunEvent::Exit`, смотря кого Windows известила первым).
- `src-tauri/src/session_end/windows.rs` — скрытое окно (`WS_EX_TOOLWINDOW`, без `WS_VISIBLE`): `WM_QUERYENDSESSION` → `ShutdownBlockReasonCreate(BLOCK_REASON)` → запись → `ShutdownBlockReasonDestroy` → TRUE; `WM_ENDSESSION` → обработчик. Новая функция привязок `windows`: `Win32_System_Shutdown` (тот же крейт 0.62.2, новых крейтов нет).
- `lib.rs`: `SessionEnd` в состоянии, окно создаётся в `setup` (главный поток), `RunEvent::Exit` завершает браузер, если сеанс завершается.
- `closing.rs`: `begin` — `pub(crate)`, `end_browser` — `pub(crate)`, новый `begin_exit(app)`.
- Контракт v1 и интерфейс **не менялись**: используется то же событие и те же ответы, что при закрытии окна. `src/editor/sessions.ts` не тронут.

## Тесты

- Модульные (`session_end/tests.rs`, подменный runtime): все окна хранилищ опрошены, окно без хранилища — нет, ожидание длится до последнего ответа, очередь разбирается; предел без ответов; окно, которое уже закрывается, не опрашивается второй раз, но ждётся; вложенный запрос; отмена и подтверждение конца сеанса, браузер завершается один раз. На Windows — `hidden_window_answers_query_and_reports_both_messages` (окно отвечает TRUE и передаёт оба сообщения).
- Красные до кода: модульные — на заглушке (4 из 6 падали); сценарный — коммит e24b6d0 без реализации (CI, см. отчёт задачи).
- Сценарный `tests/e2e/session-end.test.ts` (Windows): помощник PowerShell шлёт `WM_QUERYENDSESSION`, затем `WM_ENDSESSION(TRUE)` всем окнам верхнего уровня процесса — как Windows при выходе из системы. (1) WebDriver, «медленный диск» 1 с: ввод → сразу конец сеанса → файл содержит ввод, все окна ответили «можно», ответ быстрее 5 с. (2) Без драйвера: `oneauth.dll` в процессе браузера не появился, временная папка движка удалена.

## Ревью безопасности (инварианты)

1. Сеть — нет: только сообщения окон своего процесса; новых крейтов нет.
2. Записей вне хранилища нет новых; окно и причина задержки — объекты сеанса Windows, на диск не пишутся.
3. Строка причины и строка журнала (stderr) — постоянные, без имён и текста заметок.
4. Ввод пишется тем же путём, что при закрытии окна (ожидаемая версия, конфликт — обе версии). Остаток — аварийное завершение (см. `SECURITY.md`, «Известные ограничения»).
5. `SECURITY.md`: новая строка в таблице файлов, ограничение сужено; `CHANGELOG.md`.

## Замечания и отложенное

- **Отказ записи при конце сеанса.** Интерфейс отвечает так же, как при закрытии: при сбое показывает уведомление «Окно не закрыто…» и отвечает `window_close_cancel`. Если выход отменён, текст уведомления говорит про закрытие окна, а не про выход; и в течение минуты после этого закрытие окна закроет его без сохранения (логика 0.7). Редкий путь (сбой записи + отмена выхода); отдельное событие с полем «конец сеанса» потребовало бы расширения контракта v1 — не делалось.
- **Причина задержки на скрытом окне.** Windows может не показывать причину для невидимого окна в списке «Эти приложения мешают завершению»; список появляется только если программа не ответила за ~5 с, а предел — 4 с. Видимые окна хранилищ причину не получают.
- **Порядок рассылки.** Windows шлёт `WM_ENDSESSION` всем процессам, в том числе процессу браузера WebView2. Запись идёт на этапе `WM_QUERYENDSESSION`, до этой рассылки. Настоящий выход из системы проверяется владельцем вручную.
- Вложенный разбор очереди внутри оконной процедуры — как модальный цикл; если `WM_QUERYENDSESSION` придёт, пока главный поток в модальном окне ядра (системный диалог), события Tauri копятся до его закрытия — запись ждёт предела 4 с.
