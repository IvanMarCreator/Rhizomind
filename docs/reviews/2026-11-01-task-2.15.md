# Задача 2.15 «Enter продолжает списки, задачи и цитаты» (01.11.2026)

Ветка `task/2.15-list-continuation` от `main` d49451d. Решение владельца 92 (спецификация, раздел 12), С3.3; правила 80 и 81 (горячие клавиши).

## Что сделано

Отдельное расширение `src/editor/list-continuation.ts` (`listContinuation()`), подключено одной строкой в `src/editor/codemirror.ts` — работает в обоих режимах редактора. Чистые функции `continueMarkup(state)` и `indentList(state, direction)` возвращают правку или `null` («правило не действует»).

| Нажатие | Где | Результат |
|---|---|---|
| Enter в конце пункта | `- а`, `* а`, `+ а`, `\t- а` | новая строка с тем же отступом, маркером и пробелами после маркера |
| | `- [ ] а`, `- [x] а`, `1. [x] а` | новая задача всегда `[ ]` |
| | `1. а`, `9) а` | следующий номер (`2.`, `10)`); пункты ниже того же уровня перенумеровываются до пустой строки, другого уровня цитаты или строки с меньшим отступом; вложенные строки пропускаются |
| | `> а`, `> > а`, `>а`, `> - а` | те же префиксы цитаты (как написаны), за ними — следующий пункт |
| Enter посреди пункта | `- раз¦два` | `- раз` / `- ¦два` — строка разрывается, продолжение с маркером (как в Obsidian); текст после курсора не меняется |
| Enter на пустом пункте | `\t- ¦`, `    - ¦` | вложенный — на один шаг отступа выше (как в Obsidian) |
| | `- ¦`, `- [ ] ¦`, `2. ¦` | верхний уровень — маркер удаляется, строка пустая (выход из списка) |
| | `> - ¦` | удаляется маркер, цитата остаётся `> ` |
| | `> ¦`, `> > ¦` | удаляется внутренний `>`: `` / `> ` |
| Tab / Shift+Tab | пункт списка (и пункты под выделением) | вложенность ±1 шаг вместе с вложенными строками пункта (строки ниже с большим отступом до первой пустой); в цитате отступ ставится после `> `; Shift+Tab на верхнем уровне ничего не меняет, но нажатие остаётся редактору |

**Шаг отступа (решение исполнителя).** По стилю документа: ближайший к строке вложенный пункт в сплошном блоке строк (до 200 строк вверх и вниз, до пустой строки) — табуляция или пробелы; ширина пробелов — наименьший ненулевой отступ пунктов блока (2, 3, 4…). Вложенных пунктов нет — **табуляция**, как в Obsidian по умолчанию («Use tabs» включено): заметка, начатая в Rhizomind, откроется в Obsidian с той же вложенностью. Уменьшение отступа снимает одну табуляцию или до ширины шага пробелов.

**Где правило не действует** (обычный Enter, Tab не перехватывается): обычный текст, заголовок, линия `- - -`, `-текст`, номер из 10 цифр; курсор до маркера или в отступе; блок кода (в том числе незакрытый) и блок свойств — по готовому разбору блоков (`inCodeAt` из `live-preview/index.ts`, поле `blockTracking` есть в обоих режимах); непустое выделение и несколько курсоров (Enter); только чтение; набор через IME (`view.composing || view.compositionStarted`).

**Порядок сочетаний.** Расширение — `Prec.high`: важнее `defaultKeymap` (обычный Enter), но ниже списка подсказок вики-ссылок (`Prec.highest`, `autocomplete.ts`): при открытом списке `[[` Enter и Tab выбирают подсказку.

**Отмена.** Продолжение — одна транзакция (вставка и перенумерация вместе), `userEvent: 'input'` (не склеивается с предыдущим набором): Ctrl+Z возвращает текст и курсор до Enter. Tab — `input.indent`, Shift+Tab — `delete.dedent`, как у команд CodeMirror.

**Реестр горячих клавиш — без изменений (правило 81).** Enter и Tab — клавиши правки текста, команд окна у них нет: Tab нет в списке назначаемых клавиш (`hotkey_keys`, `chordFromEvent` даёт `null`), Enter без модификатора назначить нельзя (не в `hotkey_bare_keys`). Значит, окно (фаза перехвата `Shell.svelte`) их у редактора не заберёт; это закреплено тестом в `list-continuation.test.ts`. Показывать в настройках как переназначаемые команды незачем: это поведение текста, как Backspace.

**Навигация Tab.** Вне пункта списка Tab, как и прежде, уходит браузеру — фокус переходит к следующему элементу окна (компонентный тест: `defaultPrevented === false`). В пункте списка Tab меняет вложенность и фокус не уводит — как в Obsidian; выйти из текста с клавиатуры можно, поставив курсор вне списка (или режимом фокуса CodeMirror: Esc, затем Tab).

## Отличия от Obsidian и границы

- Текст после курсора при разрыве пункта переносится как есть (пробелы в начале не срезаются) — правило «не менять байты, которых не трогали».
- Перенумерация — только при Enter; при Tab/Shift+Tab и удалении строк номера не пересчитываются (в Obsidian 1.x — «умные списки» пересчитывают). Кандидат в отложенное.
- Пустой пункт в цитате выходит из списка, оставляя `> `; второй Enter убирает и цитату.
- Пустая строка внутри списка («свободный» список) завершает область перенумерации и поиска вложенных строк.

## Безопасность (инварианты)

Сеть, файлы и хранение не затронуты: расширение только правит текст в редакторе транзакциями CodeMirror; запись — прежним путём сессии. `docs/SECURITY.md` не меняется. Инвариант 4: правки — обычный ввод пользователя, отменяются Ctrl+Z; в режиме только чтения правило не действует.
