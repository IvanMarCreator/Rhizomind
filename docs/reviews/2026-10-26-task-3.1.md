## Найденное

### Н1. Ctrl+N не создаёт заметку (С3.5) — средняя
- **Шаги:** открыть хранилище, выбрать заметку в дереве, нажать Ctrl+N.
- **Ожидалось (С3.5):** новая заметка по настройке «где создавать новые заметки» (по умолчанию — в корне), «Без названия», поле имени.
- **Получилось:** ничего. В коде сочетания нет: `src/shell/Shell.svelte` обрабатывает только Ctrl+O и Alt+←/→; в плане (2.7) Ctrl+N не назван ни в одной задаче.
- **Тест:** `release.test.ts`, «С3.5: Ctrl+N — новая заметка (находка Н1: не сделано)» — `it.fails`: покраснеет, когда Ctrl+N появится; тогда снять пометку.
- **Рекомендация:** сделать вместе с 2.8б (там настройка «где создавать новые заметки», решение 49 связывает с ней и Ctrl+O).

### Н2. Заголовок окна хранилища — всегда «Rhizomind» (Э1, Э4б) — низкая
- **Ожидалось (макеты Э1, Э3, Э4б, Э10б):** «<заметка> — <хранилище> — Rhizomind»; после переименования — новое имя (Э4б, шаг 4).
- **Получилось:** у всех окон хранилищ заголовок «Rhizomind» (`main_window_title`, `src-tauri/src/lib.rs`). При двух открытых хранилищах окна на панели задач и в Alt+Tab не различить. Окно управления — «Управление хранилищами — Rhizomind», как в макете.
- Снимок WebDriver заголовок ОС не захватывает; найдено по коду и макету.

### Н3. Синяя рамка вокруг текста заметки при вводе (Э1) — низкая
- **Шаги:** открыть заметку, щёлкнуть в текст.
- **Ожидалось (Э1):** текст без рамки.
- **Получилось (обе ОС):** прямоугольная рамка фокуса вокруг всей области текста (≈ 700 × 350 px) — снимки `release-15-typed-saved-{light,dark}-{linux,win32}.png`. `NoteText.svelte` убирает `outline` у `.cm-editor.cm-focused`, но рамку рисует движок у самого `contenteditable` (`.cm-content`).
- **Исправлено в задаче 2.10** вместе с Н7: `.cm-content { outline: none }` из базовой темы CodeMirror.

### Н4. Путь хранилища под наведением обрезается без многоточия (Э11а) — косметика

### Н6. Очень длинная строка без пробелов в файле «только чтение» не переносится — косметика

### Н7. Базовые стили CodeMirror не применяются: отступы и пробелы подряд не видны (С3.3) — высокая
- **Шаги:** открыть заметку со строкой `  - Вложенный пункт` (или код с отступом), в любом режиме.
- **Ожидалось:** пробелы в начале строки видны — вложенный пункт сдвинут, отступы кода сохраняются на экране.
- **Получилось (Windows и Linux, CI 40404298309 и локально):** у текста `white-space: normal` — пробелы в начале строки и подряд схлопываются, вложенный пункт стоит вровень с родителем (`preview-01-…`, `preview-05-source-mode-…`); в файле пробелы есть. Причина (проба): базовая тема CodeMirror (`.cm-editor { display: flex }`, `.cm-content { white-space: pre-wrap }` и др., классы `ͼ1 ͼ2` на месте) вставляется пакетом `style-mod` элементом `<style>`, а CSP окна `style-src 'self'` (`src-tauri/tauri.conf.json`) его запрещает; на Linux `adoptedStyleSheets` — 0 (WebKitGTK), `.cm-editor` — не `flex`. На Windows (WebView2) итог тот же — `white-space: normal`, снимки `preview-0*-win32`; путь, которым там теряются стили, отдельно не разбирался.
- **Тест:** `live-preview.test.ts`, «пробелы в начале строки видны…» — `it.fails` на обеих ОС. Риск для данных: пользователь не видит отступов, которые есть в файле (вложенные списки, код), и может их «исправить» вслепую; файл при этом не портится.
- **Варианты исправления (решает разработчик/ИБ):** (а) повторить нужные правила базовой темы CodeMirror в своём CSS (`NoteText.svelte`) — без смены CSP; (б) хэш или nonce для стилей — у `style-mod` текст правил меняется, хэши хрупкие; (в) `'unsafe-inline'` для стилей — ослабляет CSP, не рекомендуется. Рекомендация — (а).
- Вероятно, та же причина у **Н3** (рамка фокуса вокруг текста) и у плотной вёрстки ниже.
- **Исправлено в задаче 2.10:** правила базовой темы — статическим файлом `src/editor/codemirror-base.css`, CSP та же; `it.fails` снят. Причина подтверждена и для Chromium (движок WebView2): `style-mod` монтирует стили в `document`, у которого есть `head`, — всегда элементом `<style>`, не `adoptedStyleSheets`; у этого элемента `sheet === null` и нарушение `style-src 'self'` в консоли.

### Н8. Отличия оформления живого предпросмотра от Э1 — низкая
- Вложенная цитата `> >` — одна полоса слева, вложенность не видна (`preview-02-cursor-outside-top-*`).
- Маркеры списка стоят у самого края колонки; в Э1 пункт сдвинут на ≈ 20 px.
- Внешняя ссылка без значка «↗» (в Э1 — «портале регламентов ↗»).
- Заголовок 1 того же размера, что имя заметки над текстом (28 px); над заголовками нет дополнительного отступа (в Э1 перед «Решения» есть) — заголовки 3–6 почти не отличаются от жирного текста.
- Блок кода: строки ограды скрыты, но занимают по строке сверху и снизу — поля блока больше, чем в Э1.
- Режим исходного текста — пропорциональный шрифт (моноширинный — «в следующем выпуске», решение оркестратора 74) — верно.
- Переключатель «книга/карандаш» (Э13, состояния 1 и 2) совпадает: нажатая кнопка на подложке с рамкой, вторая без фона.
