## Что сделано

- **`tests/e2e/release.test.ts`** — один пользовательский путь от начала до конца на настоящем ядре, 27 шагов, снимок экрана на каждом шаге (`test-results/e2e/release-NN-…`), ключевые экраны в светлой и тёмной теме: первый запуск → создание хранилища → дерево (новая заметка и папка, проверка имени, Ctrl+Z в поле, переименование тремя способами, Ctrl+Z после переименования, перетаскивание, контекстное меню, не-Markdown файлы) → редактор (индикатор «Сохраняется → Сохранено», автосохранение, LF без BOM, перенос длинной строки, запись при переходе к другой заметке, файл больше лимита) → быстрый переход (поиск, создание) → история (Alt+←/→ и кнопки) → удаление → второе хранилище через «Управление хранилищами…» → переключатель (фокус на открытое) → ввод во втором хранилище → **перезапуск программы: открыто последнее хранилище и последняя заметка с текстом** → повторный запуск (Windows) → «Убрать из списка».

- Перед перезапуском тест ждёт выхода прошлого процесса (до 20 с): конец сессии WebDriver закрывает окна, а программа выходит после записи ввода (решение 53). Без ожидания второй запуск упирался в замок одного экземпляра («Rhizomind уже запущен») — это не ошибка программы, а свойство теста.

Проверено: `xvfb-run npx vitest run --config vitest.e2e.config.ts tests/e2e/release.test.ts` (Linux, локально): **25 passed, 1 expected fail (Ctrl+N), 1 skipped (повторный запуск — только Windows)**, 57 с. Весь набор сценарных тестов локально на Linux — зелёный (кроме `release-binary.test.ts`: нужна выпускная сборка). CI — в отчёте задачи.

## Найденное

### Н1. Ctrl+N не создаёт заметку (С3.5) — средняя
- **Шаги:** открыть хранилище, выбрать заметку в дереве, нажать Ctrl+N.
- **Ожидалось (С3.5):** новая заметка по настройке «где создавать новые заметки» (по умолчанию — в корне), «Без названия», поле имени.
- **Получилось:** ничего. В коде сочетания нет: `src/shell/Shell.svelte` обрабатывает только Ctrl+O и Alt+←/→; в плане (2.7) Ctrl+N не назван ни в одной задаче.
- **Тест:** `release.test.ts`, «С3.5: Ctrl+N — новая заметка (находка Н1: не сделано)» — `it.fails`: покраснеет, когда Ctrl+N появится; тогда снять пометку.
- **Рекомендация:** сделать вместе с 2.8б (там настройка «где создавать новые заметки», решение 49 связывает с ней и Ctrl+O).

### Н2. Заголовок окна хранилища — всегда «Rhizomind» (Э1, Э4б) — низкая
- **Ожидалось (макеты Э1, Э3, Э4б, Э10б):** «<заметка> — <хранилище> — Rhizomind»; после переименования — новое имя (Э4б, шаг 4).
- **Получилось:** у всех окон хранилищ заголовок «Rhizomind» (`main_window_title`, `src-tauri/src/lib.rs`). При двух открытых хранилищах окна на панели задач и в Alt+Tab не различить. Окно управления — «Управление хранилищами — Rhizomind», как в макете.
- Снимок WebDriver заголовок ОС не захватывает; найдено по коду и макету.

### Н3. Синяя рамка вокруг текста заметки при вводе (Э1) — низкая
- **Шаги:** открыть заметку, щёлкнуть в текст.
- **Ожидалось (Э1):** текст без рамки.
- **Получилось (Linux, WebKitGTK):** прямоугольная рамка фокуса вокруг всей области текста (≈700 × 350 px) — снимок `release-15-typed-saved-{light,dark}-linux.png`. `NoteText.svelte` убирает `outline` у `.cm-editor.cm-focused`, но рамку рисует движок у самого `contenteditable` (`.cm-content`). Снимок Windows — из CI этой ветки (см. отчёт); если там рамки нет — только Linux.

### Н4. Путь хранилища под наведением обрезается без многоточия (Э11а) — косметика
- В строке под мышью путь обрезается кнопками «Открыть» и «…» посреди символа, без «…» (`vaults-manager-menu-light-win32.png`, `release-28-removed-from-list-linux.png`); в строке без наведения многоточие есть.

### Н5. Расхождения текстов с макетом (Э4, Э11а–б) — косметика, решение за дизайнером
- Э4: ошибка имени в макете называет символ («Символ «:» нельзя использовать в имени. Также запрещены…»), в приложении — общий текст «В имени нельзя использовать символы \ / : * ? " < > |».
- Э11а–б: внизу окна в макете «Работает без сети. Данные хранилища — только в его папке…», в приложении — «Список хранилищ хранится только на этом компьютере.» (осознанно изменено в 2.8б по ревью; макет не обновлён).
- Э11а: пункта «Показать в Проводнике» нет — по решению 63, верно.

### Н6. Очень длинная строка без пробелов в файле «только чтение» не переносится — косметика
- Файл 11 МБ из одного «слова»: строка уходит за правый край колонки (`release-17-read-only-linux.png`). Обычный текст переносится (проверено в сценарии: `scrollWidth` текста не больше ширины). Крайний случай, вероятно предел CodeMirror для гигантской строки.

### Проверено и ошибкой не оказалось
- На снимках CI `switcher-tab` (обе ОС) под окном быстрого перехода не видно открытой заметки. Причина — окно Ctrl+O (600 px, отступ 64 px сверху) закрывает заголовок и первые строки короткой заметки; на макете Э3 так же. Подтверждено пробой (`elementsFromPoint`).

### Особенности среды тестов (не ошибки приложения)
- **WebKitWebDriver после правого клика мышью перестаёт вводить не-ASCII символы** в поля страницы (латиница вводится, кириллица приходит как `key = Unidentified` без `input`). Поэтому контекстное меню в сценарии открывается с клавиатуры (Shift+F10); правый клик проверяют компонентные тесты дерева. На Windows (msedgedriver) не проверялось отдельно.
- Конец сессии WebDriver не завершает программу мгновенно: окна закрываются через цикл записи ввода (решение 53); перезапуск с тем же профилем ждёт выхода.
