# Задача 0.5 «Один экземпляр программы» — отчёт разработчика и самопроверка (26.10.2026)

Решения владельца 57 (один экземпляр, повторный запуск переключает на открытое окно) и 58 (при повторном запуске — окно «Управление хранилищами», задача 2.8). Независимые ревью кода и безопасности — за оркестратором.

## Что сделано
- `src-tauri/src/single_instance/` — свой механизм без новых крейтов (плагин отклонён: `tokio/net`, `zbus`, `socket2` — `docs/research/2026-10-26-single-instance.md`).
  - Windows: мьютекс `Local\Rhizomind.SingleInstance` + окно «только для сообщений» класса `Rhizomind.SingleInstance`; второй запуск — `AllowSetForegroundWindow` + `WM_COPYDATA` (метка `0x525A0001`, без данных), до 5 с повторов, пока первый запускается или завершается.
  - Linux, macOS: `flock` на `data_local_dir()/Rhizomind/instance.lock`; второй — «Rhizomind уже запущен» в stderr, выход (до 1 с ждёт освобождения замка завершающимся экземпляром).
  - Тестовая сборка (`webdriver`): имя `…webdriver`, замок `instance-webdriver.lock` в папке профиля сценарного теста.
- `lib.rs::run`: `single_instance::claim()` — первой строкой, до `Shell::prepare` (временная папка WebView2, уборка остатков), до `startup_registry` (`vaults.json`) и до движка. `handle_run_event`: на `Exit` имя освобождается до ожидания процесса браузера.
- Учёт активного окна: `single_instance::on_window_event` (фокус / закрытие) в общем `on_window_event`.

## Точка «повторный запуск» для задачи 2.8
`single_instance::on_second_instance(app: &AppHandle<R>)` в `src-tauri/src/single_instance/mod.rs` — единственный обработчик; вызывается в главном потоке (через `run_on_main_thread` из обработчика окна для сообщений, подключение — `setup` в `lib.rs`). Сейчас выводит вперёд последнее активное **показанное** окно (`RecentWindows::target`, затем `windows::focus`). 2.8 заменяет тело на открытие окна «Управление хранилищами» (или фокус на него, если уже открыто). Обычный запуск не меняется: открывается последнее хранилище. Когда появится путь хранилища в аргументах — новая версия метки протокола и данные в `WM_COPYDATA`, разбор — в `window_proc` (`windows.rs`), передача в `on_second_instance`.

## Самопроверка безопасности
- Инвариант 1: сокетов, именованных каналов, D-Bus нет; новых крейтов нет; к `windows` добавлены только функции привязок (`Win32_Security`, `Win32_Graphics_Gdi`, `Win32_System_DataExchange`).
- Инвариант 2: новая запись вне хранилища только на Linux/macOS — пустой `instance.lock` (строка в SECURITY.md); на Windows записей нет. Имена без путей и имён хранилищ.
- Окно для сообщений принимает только `WM_COPYDATA` с меткой; данные не читает; действие — вывести вперёд уже показанное окно. Скрытое окно Windows (до проверки InPrivate) не трогается — `unminimize` показал бы его в обход проверки.
- Принятый риск: другой процесс того же пользователя может заранее создать мьютекс с этим именем и тем самым не дать Rhizomind запуститься (DoS) или слать сигнал «вывести окно вперёд». Процесс того же пользователя может и больше; данных это не раскрывает.
