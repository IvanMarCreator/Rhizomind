## Сомнения

1. **Изоляция событий: что гарантирует Tauri** (исправлено по ревью безопасности — см. раздел ниже; первая версия считала случайные метки достаточными, это неверно). Tauri 2.12 отдаёт событие, отправленное окну (`emit_to(EventTarget::WebviewWindow)`), и всем слушателям интерфейса с целью `Any` в **любом** окне: `emit_js_filter` перебирает все WebView, а `match_any_or_filter` пропускает цель `Any` без фильтра (`tauri-2.12.5/src/event/listener.rs`). Слушатель с целью `WebviewWindow{label: X}` в окне Б тоже получает события окна X. Значит, сам Tauri изоляцию не гарантирует. Защита в 1.3: (а) фильтр изолированного iframe не пропускает `listen` без цели «окно с меткой» (код страницы его не обойдёт: непрошедший фильтр вызов не шифруется ключом iframe и ядром отклоняется); (б) метки окон случайные, 64 бита — метку чужого окна интерфейс не знает (в событиях и ответах команд меток нет, права `plugin:window|get_all_windows` у окна нет). Проверить в Rust-тесте, что JS-слушатель `Any` другого окна не получил событие, нельзя: подменный runtime Tauri не исполняет JS, а сценарный тест открывает одно окно. Тест на стороне Tauri с двумя окнами — `events_reach_only_the_window_of_their_vault` (слушатели Rust с целью окна, 1.7).
2. **Команда «открыть окно управления хранилищами»** для пункта «Управление хранилищами…» переключателя (С3.1) в контракте v1 отсутствует — понадобится в 2.8 (расширение контракта).
3. **Второй экземпляр приложения** может открыть то же хранилище во втором окне; `vaults.json` — последняя запись побеждает.
4. «Убрать из списка» открытое хранилище: окно остаётся открытым и работает; при закрытии его размер не запоминается (хранилища нет в списке).
