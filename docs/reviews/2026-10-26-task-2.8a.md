# Задача 2.8а «Управление хранилищами и переключатель» — что сделано и что отложено (26.10.2026)

Ветка `task/2.8a-vault-manager` от `main` b06b550. Решения владельца 58, 59; спецификация С3.1; макеты Э10б (29-638), Э11а (31-2), Э11б (31-259), Э11в (31-420). Окно «Настройки хранилища» (Э12) — не делалось (2.8б, после КТ1).

## Решение: где живёт окно «Управление хранилищами»

**Отдельное окно приложения без хранилища, одно на программу** (как в Obsidian; макет Э11 — окно 920 × 600 со своим заголовком «Управление хранилищами — Rhizomind»).

- Создаёт ядро: `windows::open_manager` → `create_manager_window` (общая с окнами хранилищ функция `build_window` в `lib.rs`: InPrivate, временная папка данных, флаги, запреты переходов, новых окон, загрузок, разрешений, проверка InPrivate до показа). Метка `vault-<16 случайных шестнадцатеричных цифр>`, та же capability, что у окон хранилищ: **новых прав Tauri нет**, фильтр isolation не ослаблен (в список команд добавлена одна своя команда).
- Окно управления уже открыто — новый вызов даёт ему фокус (`Core::reserve_manager`: одно окно и при одновременных вызовах; замков на время создания окна не держит — можно звать из главного потока).
- Хранилище к окну управления не привязывается (`Core::claim_vault` отказывает «окно занято»): выбранное хранилище открывается в своём окне (или получает фокус, если уже открыто), после чего ядро закрывает окно управления (`close_manager`).
- Интерфейс узнаёт окно управления по `vault_current` без хранилища: `Shell.svelte` показывает `VaultManager` вместо оболочки. Других окон без хранилища больше нет: при запуске без последнего хранилища (первый запуск, папка недоступна) открывается окно управления — при пустом списке это Э11б.
- Размер и положение окна управления не запоминаются (в `vaults.json` ничего нового).

## Сомнения и вопросы

1. **Отдельная capability для окна управления** (пожелание обзора 0.4, отложено в 1.3): сейчас у окна управления и у окон хранилищ одни права, как в постановке («не шире»). Можно сузить: окнам хранилищ оставить из группы «Хранилища» только `vault_list`, `vault_current`, `vault_open`, `vault_manager_open`, а `vault_create`, `vault_open_folder`, `vault_remove_from_list` выдать только окну управления (другой шаблон метки, например `manager-*`). Не сделано без решения владельца/оркестратора.
2. Текст внизу окна «в профиле Windows — лишь список хранилищ» взят из макета; по `SECURITY.md` вне хранилища есть ещё временная папка WebView2 (удаляется) и известные следы Windows (Credentials, окно выбора папки). Возможно, стоит уточнить текст после расследования 0.6.
3. Ручная проверка на Windows: размер окна управления 920 × 600, системный заголовок, закрытие окна управления после открытия хранилища — снимками CI видна только страница.
