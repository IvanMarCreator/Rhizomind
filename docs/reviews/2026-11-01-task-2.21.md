## 1. Перенумерация

- **Когда.** Tab / Shift+Tab в пункте (`indentList`) и удаление, убравшее перенос строки: Backspace в начале строки, Delete в конце, вырезание, удаление выделения (`delete.*`, кроме `delete.dedent` — Shift+Tab считает сам). Удаление внутри строки номера не трогает. Ввод, вставка, отмена, внешние изменения — не трогают (отмена возвращает байты как были).
- **Что пересчитывается.** Только списки вокруг правки: для Tab — уровень, куда пункты встали, и уровень, откуда ушли (пункт под сдвинутыми); для удаления — список на месте удаления и строкой ниже. Список одного уровня — пункты с одинаковым отступом и тем же разделителем (`.` или `)`), вложенные строки пропускаются; граница — пустая строка, другой уровень цитаты, строка мельче пункта, ненумерованный пункт. Вложенный нумерованный список — своя нумерация.
- **С какого номера (решение исполнителя).** С номера первого пункта списка (`5. 6. 7.` остаётся с 5). Если первым на уровне только что стал сдвинутый Tab / Shift+Tab пункт — с 1 (так ведут себя «умные списки» Obsidian по описанию в обзоре 2.15; на живом Obsidian не сверялось): `1. а / 2. б / 3. в` + Tab на «б» → `1. а / ⇥1. б / 2. в`; Shift+Tab из середины вложенного списка — остаток вложенного начинается с 1. При удалении первого пункта номера оставшихся не сбрасываются (`2. б / 3. в` остаётся) — текст, который не трогали, не меняется. Удаление пустой строки между двумя списками сливает их в один — нумерация сквозная (так их и показывает Markdown).
- **Ведущие нули.** Сохраняются, если номер написан с ними (`01.` → `02.`); без них ширина не добавляется (`10.` → `9.`, а не `09.` — нашлось тестом на 10 000 пунктов; прежняя `formatNumber` дописывала ноль и при Enter, когда номер становился короче, — в Enter этого не случалось, номера только росли).
- **Отмена.** Одна правка: у Tab — сдвиг и номера составлены в один `ChangeSet`; у удаления — фильтр транзакции дописывает номера в ту же транзакцию (`sequential`). Ctrl+Z — одним шагом, Ctrl+Y возвращает.
- **Скорость.** Замены номеров — одним изменением участка (`joinChanges`, как у Enter). 10 000 пунктов (vitest, jsdom, после прогрева): Enter ≈ 9–12 мс, Tab ≈ 10–14 мс, вырезание пункта ≈ 9–14 мс; первый прогон 20–40 мс. Тесты требуют ≤ 2 изменённых участков и < 200 мс (запас на общие раннеры).
- **Курсор.** Слитое изменение участка CodeMirror перенёс бы курсор к краю участка — выделение переносится по каждой замене отдельно (`mapSelection`).

## 2. Парная скобка (замечания QA 2.18)

- **Ctrl+Z / Ctrl+Y.** Через `invertedEffects` истории CodeMirror: правка, удалившая свои `]` (Ctrl+Z пары, Backspace по паре, Enter в паре), при отмене возвращает их «своими». Ctrl+Z после Backspace — скобка снова перескакивается; Ctrl+Z, Ctrl+Y пары — тоже. Оговорка: после Ctrl+Y CodeMirror ставит курсор за вернувшийся текст (за `]`), поэтому перескок нужен, только если вернуться к скобке стрелкой — тогда работает (тест). Чужая `]` отменой «своей» не становится.
- **Enter в паре (решение исполнителя).** Живого Obsidian в облачной среде нет, его поведение здесь не проверено; общее продолжение списка (как у нас до правки и у `insertNewlineContinueMarkup` CodeMirror) делит строку в месте курсора и рвёт пару (`- [` / `- ]`). Выбрано правило «пара, которую не дописали, не мешает Enter» — только для своей (только что вставленной) `]` перед курсором:
  - пустая пара `[|]` или `[[|]]` — пара убирается, дальше обычный Enter по строке без неё: `- а [|]` → `- а ` / `- |`; `- [|]` → как Enter на пустом пункте — выход из списка (вложенный — на уровень выше); в абзаце — обычный перенос;
  - пара с текстом `[а|]`, `[[Имя|]]` — курсор переходит за свои `]`, дальше обычный Enter: `- [а|]` → `- [а]` / `- |`, `1. [а|]` → `1. [а]` / `2. |`.
  Одна транзакция (Ctrl+Z — одним шагом, пара снова «своя»). При открытом списке подсказок `[[` Enter, как и прежде, выбирает подсказку. Чужая `]` — обычный Enter (продолжение списка). Чтобы Enter в паре решался раньше продолжения списков, `bracketPairs()` подключена в `codemirror.ts` перед `listContinuation()` (обе — `Prec.high`; Backspace продолжения списков не занят, конфликтов нет).
- **`\\[`.** Скобка экранирована при нечётном числе `\` перед ней: `\` и `\\\` — одна `[`; `\\`, `\\\\` — пара.

## 3. Список `[[` по Backspace

Новый список открывается транзакцией ввода `input.type` и теперь также `delete.backward` (Backspace) в незакрытой цели; запрос подсказок — по новому тексту. ## 2.21а. Enter на пустом вложенном нумерованном пункте (находка QA 2.21)

Ошибка (низкая): Enter на пустом вложенном пункте поднимал его на уровень выше без перенумерации (`1. a / ⇥1. x / ⇥2. y / ⇥3. | / 2. b` → номера верхнего уровня 1, 3, 2). Причина: `exitEmpty` делал сдвиг, как Shift+Tab, но `renumberRuns` не вызывал (удаление переноса строки в этой правке нет, фильтр удаления её не видит). Исправление в `src/editor/list-continuation.ts`: перенумерация после сдвига вынесена из `indentList` в общую `shiftWithRenumber`, её зовут Tab / Shift+Tab и подъём пустого пункта; номера — в той же транзакции (Ctrl+Z — одним шагом). Теперь: поднятый пункт → `2. `, `2. b` → `3. b`, вложенный список (1, 2) не меняется; из середины вложенного списка остаток вложенного — с 1 (как у Shift+Tab). Граничные случаи (решение исполнителя): ненумерованный `⇥- ` внутри нумерованного списка при выходе становится `- ` между пунктами и, как при Shift+Tab, нумерованные пункты не трогает (маркированный пункт — граница списка); пустой нумерованный пункт верхнего уровня — выход из списка, строка становится пустой (граница), пункты ниже остаются своим списком со своими номерами — по аналогии с удалением первого пункта (2.21: текст, который не трогали, не меняется); цитата `> ⇥2. ` — как без цитаты. Тесты (`list-continuation.test.ts`, «перенумерация после Tab и Shift+Tab»): 6 случаев Enter и отмена одним шагом; до правки красные 5 (два граничных уже вели себя так).
