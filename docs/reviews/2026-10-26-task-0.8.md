# Задача 0.8 «Своё окно выбора папки» — итог (26.10.2026)

Решение владельца 56: системное окно выбора папки через `tauri-plugin-dialog` → rfd 0.16.1 (`FOS_PICKFOLDERS`) писало путь к хранилищу в перемещаемый профиль — противоречие решению 46. Сделано своё окно на `IFileOpenDialog` по варианту `proposal` расследования 0.6 (`docs/research/2026-10-26-traces-investigation.md`).

## Что сделано
- `src-tauri/src/dialogs/folder_windows.rs`: `pick_folder(owner, title)` — `FOS_PICKFOLDERS | FOS_DONTADDTORECENT | FOS_FORCEFILESYSTEM | FOS_PATHMUSTEXIST`, постоянный `CLIENT_GUID`, `ClearClientData` после закрытия (ответ `E_FAIL` игнорируется), владелец — HWND окна вызова (модально), COM — в отдельном STA-потоке на время показа. Ошибка COM или отмена — `None` («отмена»), как раньше.
- `src-tauri/src/dialogs.rs`: на Windows `ask_folder` вызывает `folder_windows::pick_folder`; на Linux и macOS — `tauri-plugin-dialog`, как было. Сигнатуры `pick_folder`/`ask_folder`, общий замок `DialogSlot` и подмена ответов `test_answers` не менялись.
- `tauri-plugin-dialog` остаётся: окно подтверждения внешней ссылки (`external_links`), окно безвозвратного удаления (решение 55) и окно выбора папки на Linux/macOS.
- Новых крейтов нет: у `windows` 0.62.2 добавлена функция `Win32_UI_Shell`.

## Проверка
- Обычный прогон (verify, Windows): `private_settings_keep_the_folder_out_of_recent_lists` — опции, GUID, `ClearClientData`; `closed_owner_window_gives_cancel_without_dialog` — окно-владелец уже закрыт: окно выбора не показывается, ответ «отмена».
- Шаг CI «Окно выбора папки без следов в Roaming (Windows)»: `chosen_folder_path_does_not_reach_roaming_profile` (`--ignored`). Окно — в отдельном процессе (`dialog_in_child_process`), «пользователь» вводит путь с `\` в конце (переход в папку) и выбирает её, `SetFolder` не вызывается. После выхода процесса метка из пути ищется во всём HKCU, кроме `Software\Classes\Local Settings`, в именах файлов `%APPDATA%` и в содержимом `%APPDATA%\Microsoft\Windows\Recent`. Контроль (`RHIZOMIND_T08_CONTROL=1`): окно с опциями rfd — путь в Roaming есть, поиск его видит; наши опции без `ClearClientData` — в журнал.
- Красный прогон (опции как у rfd): путь найден в `ComDlg32\OpenSavePidlMRU\*`, `Explorer\RecentDocs`, ярлык `Recent\<папка>.lnk`.

## Ревью оркестратора (Б1, М1) — что вышло
- **Б1 (LastVisitedPidlMRU):** покрыть тестом CI не удалось. Опыты в ветке `task/0.8-probe` (прогоны 40293927801, 40295162228, 40296027902, 40296840203): опции rfd и наши без `ClearClientData`; папка задаётся полным путём в поле имени, `SetDefaultFolder` + имя, переходом в папку; окно в том же и в отдельном процессе с поиском после выхода — `LastVisitedPidlMRU` остаётся пустым (`MRUListEx` без записей) во всех вариантах. Оценка: Windows не ведёт эту запись для такого процесса (консольный тестовый исполняемый файл, запущенный из cargo), зонд 0.6 был GUI-процессом на C#. Стирание `LastVisitedPidlMRU` подтверждено только опытом 0.6 — так и записано в `docs/SECURITY.md`. Тест переделан ближе к пользователю (без `SetFolder`, отдельный процесс, поиск после выхода).
- **М1:** исключается только `Software\Classes\Local Settings`; формулировки в SECURITY.md, CHANGELOG, `ci.yml` поправлены.
- Пожелания: сбой COM пишется в stderr с шагом и HRESULT (без пути); нет HWND окна — запись в stderr, окно без владельца; закрытый владелец — окно не показывается (тест).
- При слиянии main (2.8а): окно выбора папки на Windows тоже берёт ответ из `RHIZOMIND_E2E_PICK_FOLDER` в тестовой сборке — иначе сценарный тест на Windows открыл бы настоящее окно.
