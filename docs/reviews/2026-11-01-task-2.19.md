# Задача 2.19 «Своё контекстное меню вместо меню движка» (01.11.2026)

Ветка `task/2.19-context-menu` от `main` 31850a2 (+ слияние 107f202 — решение владельца 98). Решение оркестратора 97 (спецификация, раздел 12), следует из решений 94/96 и инварианта 4; решение владельца 98 — «Вставить» через команду ядра.

## Что найдено

Tauri 2.12.5 не передаёт `with_default_context_menus`, и wry оставляет `AreDefaultContextMenusEnabled = true` (`vendor/wry/src/lib.rs:1769`). Действие `contextmenu` гасило только дерево. В меню WebView2 есть «Обновить», «Сохранить как», «Печать»; у WebKitGTK — «Назад/Вперёд/Обновить».

## Как выключено

1. **Движок (Windows).** `disable_browser_accelerator_keys` (2.17) дополнена соседней мерой `disable_default_context_menus`, `src-tauri/src/security/windows.rs`: она ставит `ICoreWebView2Settings::AreDefaultContextMenusEnabled = false` в `harden_platform_webview` (`src-tauri/src/lib.rs`) — в каждом окне, до показа.
2. **Движок (Linux).** `security::disable_webkit_context_menu`: сигнал WebKitGTK `context-menu` отвечает «обработано», меню «Назад/Вперёд/Обновить» не строится (`harden_platform_webview`; прямая зависимость `webkit2gtk 2.0.2` для Linux — тот же крейт, что у wry, новых крейтов нет).
3. **Интерфейс (второй рубеж).** `blockEngineContextMenu(document)` в `src/main.ts` гасит действие `contextmenu` по умолчанию в фазе перехвата, везде. Распространение события не останавливается: своим меню (дерево, правка текста) событие доходит.
4. **Своё меню правки текста** (`src/shell/textMenu.ts`, показывает `Shell.svelte`): в тексте заметки (CodeMirror, находится через `EditorView.findFromDOM`) и в полях ввода (`input` текстовых типов, `textarea`).
   - Пункты: «Вырезать» (Ctrl+X), «Копировать» (Ctrl+C), «Вставить» (Ctrl+V), «Выделить всё» (Ctrl+A).
   - Без выделения «Вырезать/Копировать» серые; в режиме только чтения серый «Вырезать».
   - «Вставить» активен в окне хранилища (в режиме только чтения — серый), в окне управления хранилищами — серый (права команды там нет, Ctrl+V работает).
   - «Вырезать/Копировать» возвращают фокус в редактор или поле и выполняют команду движка `copy`/`cut` — тот же путь, что у Ctrl+C/Ctrl+X, через системный буфер; CodeMirror обрабатывает их своим обработчиком. Выбор: `execCommand` по щелчку пользователя надёжен в WebView2 и WebKitGTK (сценарный тест на обеих ОС: «Копировать» из меню, затем Ctrl+V), поэтому `clipboard_write_text` не понадобился — ядро в буфер не пишет. «Выделить всё» — `selectAll` CodeMirror или `select()` поля.
   - Правый щелчок вне выделения ставит курсор в точку щелчка (`posAtCoords`), внутри выделения — оставляет выделение.
   - Shift+F10 и клавиша меню открывают меню у курсора.
5. **Общий компонент меню** `src/shell/ContextMenu.svelte` (бывший `src/tree/TreeMenu.svelte`, вид по макету меню дерева):
   - новые возможности: название меню и неактивные пункты — серые, `aria-disabled`, клавиатурный фокус их пропускает;
   - если активных пунктов нет, фокус ставится на само меню, чтобы работал Esc;
   - слой поднят до 60 — меню видно и над окном настроек;
   - клавиатура: ↑/↓, Home/End, Enter, Esc, Tab; меню закрывается и щелчком мимо;
   - если фокус вернулся туда, где щёлкнули (так делает WebKitGTK после `contextmenu`; найдено сценарным тестом на Linux), Esc и Tab всё равно закрывают меню, а стрелки уводят фокус в меню.
6. **Мелкие правки.** В поле переименования дерева теперь меню правки текста, а не меню дерева (`FileTree.svelte`). Быстрый переход отпускает фокус в меню над своим полем (`QuickSwitcher.svelte`, `onFocusIn`); после закрытия меню фокус возвращается в поле.
7. **Остальные места** (лента, шапка, пустая область, окно управления хранилищами): правый щелчок ничего не делает. Меню дерева — как было.

## «Вставить» — команда ядра `clipboard_read_text` (решение 98)

Программно прочитать буфер страница могла бы только через Clipboard API: в WebView2 это разрешение ClipboardRead (`vendor/wry/src/webview2/mod.rs:534,561`), в WebKitGTK — `javascript_can_access_clipboard`. Оба остаются выключены. Вместо этого:

- **Команда** `clipboard_read_text` без параметров → `{ outcome: 'text', text } | { outcome: 'empty' } | { outcome: 'too_large', limit_bytes } | { outcome: 'not_focused' }`. Ошибки: `no_vault_open`, `io_failed`. Контракт v1 — `contracts/v1/clipboard_read_text.snap`, `enums.snap`; типы TS и Rust; фильтр isolation; сгенерированный файл прав `src-tauri/permissions/autogenerated/clipboard_read_text.toml`.
- **Чтение.**
  - Windows: только `CF_UNICODETEXT` (`src-tauri/src/clipboard/windows.rs`, крейт `windows`, новая функция `Win32_System_Memory`). Если число единиц UTF-16 больше предела, текст не переводится.
  - Linux: GTK `CLIPBOARD` в главном потоке (`src-tauri/src/clipboard/gtk.rs`). Крейт `gtk 0.18.2` уже был в дереве через tauri/wry, теперь он ещё и прямая зависимость для Linux; новых крейтов нет.
- **Рубежи.**
  - Право `allow-clipboard-read-text` есть только у окон хранилищ (`capabilities/main.json`).
  - В ядре: окно с хранилищем (`no_vault_open`) и в фокусе (`not_focused` — фоновое или скрытое окно буфер не читает).
  - Предел — «Максимальный размер файла для редактирования» хранилища; длиннее — уведомление, текст не вставляется.
  - Ядро ничего не пишет, не хранит и не журналирует.
- **Вызов.** Только `paste` в `src/shell/textMenu.ts` по щелчку по пункту. Построение и открытие меню буфер не читают (тесты `textMenu.component.test.ts`, `Shell.component.test.ts`).
- **Вставка.**
  - В редакторе — одна транзакция `replaceSelection` (`userEvent: input.paste`): одна отмена Ctrl+Z, автосохранение как у ввода. Режим только чтения проверяется заново после ответа ядра.
  - В поле — `insertText` движка (событие `input`, отмена); переносы в однострочном поле заменяются пробелами.

## Ручная проверка владельцем (Windows)

1. Правый щелчок в тексте заметки: меню Rhizomind из четырёх пунктов, без «Обновить», «Сохранить как», «Печать». Без выделения «Вырезать/Копировать» серые.
2. Выделить слово → правый щелчок по нему → «Копировать» → правый щелчок в другом месте → «Вставить» вставляет слово; Ctrl+Z отменяет вставку. Скопировать текст в Блокноте → «Вставить» в Rhizomind (и наоборот) — буфер общий. «Вырезать» убирает слово. «Выделить всё» выделяет заметку.
3. Скопировать в буфер очень большой текст (больше «Максимального размера файла для редактирования», например 2 МБ при пределе 1 МБ) → «Вставить» — уведомление, текст не вставлен.
4. Правый щелчок по другому слову без выделения ставит туда курсор.
5. Правый щелчок в поле быстрого перехода (Ctrl+O), в поле переименования, в числовых полях настроек — то же меню. Esc закрывает меню, фокус остаётся в поле.
6. Правый щелчок по ленте, шапке, пустой области, в окне «Управление хранилищами» — ничего. В дереве — меню дерева.
7. Shift+F10 в тексте — меню у курсора; стрелки, Enter, Esc работают.

## Исправления по QA

1. **Меню в поле нового имени** (дерево, шапка заметки) закрывало поле: меню забирало фокус, `onblur` сохранял имя. Теперь `NameField.svelte` не сохраняет имя, если фокус ушёл в `[role="menu"]`; после меню фокус возвращается в поле. Тест на настоящем поле (`ShellTree.component.test.ts`, дерево и шапка): правый щелчок → «Вставить» → текст в поле, поле открыто, `entry_rename` не вызван, Esc отменяет. Без исправления тест красный.
2. `docs/SECURITY.md`, «Буфер обмена» — описан остаточный риск: ядро не проверяет жест пользователя, любой скрипт страницы в активном окне хранилища может вызвать команду; перечислены рубежи.
3. Вставка — одна транзакция: тест считает транзакции с правкой через `updateListener` (`textMenu.component.test.ts`).
4. `src-tauri/Cargo.toml`: комментарий про `open` возвращён к его секции.
5. Контроль меню движка на Windows через `ICoreWebView2_11::ContextMenuRequested` (`webview2_runtime.rs`): при выключенном меню событие не должно приходить (иначе ошибка), при включённом на время — должно прийти (запись в журнал).
