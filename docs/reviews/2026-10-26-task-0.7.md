# Задача 0.7 «Сохранение при закрытии окна» — отчёт разработчика и самопроверка (26.10.2026)

Решение владельца 53: окно исчезает сразу, программа завершается только после того, как ввод записан на диск (с пределом ожидания). Снимает ограничение 2.4 «запись при закрытии окна уходит, но окно не ждёт ответа». Независимые ревью кода и безопасности — за оркестратором.

## Как устроено
1. **Ядро** (`src-tauri/src/windows/closing.rs`), `CloseRequested` окна хранилища:
   размер и положение окна запоминаются (`remember_placement`, до скрытия) → `prevent_close` → `hide` → событие `window:close-requested` **только этому окну** → поток ждёт ответа:
   - `window_close_ready` — окно уничтожается (`destroy`); из цикла закрытия окно выводит событие `Destroyed`;
   - `window_close_cancel` — окно показывается снова и получает фокус;
   - нет ответа за `CLOSE_TIMEOUT` = 10 с — окно уничтожается, в stderr строка без имён и текста заметок.
   Повторный `CloseRequested` во время ожидания — снова `prevent_close`, второго цикла нет. Окно без хранилища (управление хранилищами) закрывается сразу. Не удалось создать поток ожидания — окно уничтожается сразу (как до задачи), а не висит скрытым.
2. **Выход**: последнее окно уничтожается только после ответа (или предела), поэтому Tauri просит выхода, когда ждать уже нечего. Если выход попросили явно (`AppHandle::exit`), пока окна записывают, — `ExitRequested` откладывается (`exit_must_wait`), поток ждёт конца всех закрытий (предел + 2 с) и повторяет выход. Временная папка движка удаляется на `Exit`, как раньше.
3. **Интерфейс**: `Shell.svelte` подписывается на событие первым делом (до загрузки окна); `WindowClosing` (`src/shell/closing.ts`) вызывает `flushForClose` редактора (`src/editor/sessions.ts`) — запись всех заметок окна и ожидание ответов, включая записи, ушедшие раньше, повторы после `renamed` и конфликты. Заметка в состоянии «файла нет на диске» (`missing`) ждёт сигнала о переименовании до 1,5 с. Итог:
   - всё записано — `window_close_ready`;
   - что-то не записано — `window_close_cancel` + уведомление «Окно не закрыто: не удалось сохранить заметку «…». <причина> Текст остаётся в редакторе. Чтобы закрыть окно без сохранения, закройте его ещё раз в течение минуты.»; повторное закрытие в течение минуты — `window_close_ready` (иначе окно с хранилищем на вынутой флешке не закрыть никогда).
   `pagehide`/`beforeunload`/скрытие окна — оставлены запасным путём.

## Решения владельца 66, 67
- **66.** Ответ `window_close_cancel`, а папки хранилища нет и она не на несъёмном локальном томе (`vault::fsops::storage_lost`: Windows — `GetDriveTypeW` ≠ `DRIVE_FIXED` по ближайшей существующей папке, как у «диска без корзины»; Linux, macOS — папка недоступна): окно не возвращается — сначала системное сообщение «Хранилище «…» недоступно. Окно закрыто, несохранённый ввод не записан.» (`dialogs::tell_closed_unsaved`, ждёт «ОК», чтобы выход программы не убрал его), затем окно уничтожается. На внутреннем диске — окно возвращается, как раньше. Тестовая сборка: `RHIZOMIND_E2E_REMOVABLE` (только `webdriver`), сообщение — в stderr. Тесты: `failed_save_on_lost_external_storage_closes_the_window_with_message`, `failed_save_with_vault_in_place_returns_the_window`, `storage_lost_tests`; сценарные — «внешний носитель вынут» (обе ОС), «внутренний диск» (Windows).
- **67.** Предел 10 с оставлен; всё записано — ответ сразу, без записей и ожидания (`sessions.test.ts`, «решение 67…»; ядро — `ready_answer_closes_at_once`).

## Решение владельца 64: выход без OneAuth
- Последнее окно программы (`closing::is_last_window`: все другие окна уничтожены или уничтожаются; окно, ждущее записи, последним не считается) уничтожается функцией `destroy`: после записи ввода — `Shell::terminate_browser` → `WebviewDataDir::terminate_browser` → `process::terminate` (`TerminateProcess` + ожидание до 2 с, только Windows: на Linux своего процесса браузера с номером нет), затем `destroy` окна, выход, удаление временной папки (как раньше). Последнее окно без хранилища (окно управления) тоже идёт этим путём (без записи и без события).
- Тестовая сборка: `RHIZOMIND_E2E_KEEP_BROWSER` — штатное закрытие для контрольного прогона.
- Тесты: `last_window_without_vault_goes_through_browser_termination`, `last_window_is_the_one_no_other_window_outlives`; сценарный (Windows) `tests/e2e/browser-exit.test.ts`: наблюдатель PowerShell опрашивает модули процесса браузера до выхода программы — `oneauth.dll` не загружена; контроль со штатным закрытием — загружена (наблюдатель работает); новых отчётов WER/дампов нет; временная папка движка удалена.
- Не проверено здесь: кросс-проверка clippy для `x86_64-pc-windows-msvc` в облаке не собирается (`blake3` требует компилятор C для MSVC) — Windows-код проверяет CI.

## Известные ограничения
- Предел 10 с: на очень медленном сетевом диске запись, идущая дольше 7 с, не дожидается — окно возвращается с причиной «диск не отвечает».
- Выход из системы / выключение Windows (W1) — см. `SECURITY.md`, задача после КТ1.
