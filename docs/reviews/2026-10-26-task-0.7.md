# Задача 0.7 «Сохранение при закрытии окна» — отчёт разработчика и самопроверка (26.10.2026)

Решение владельца 53: окно исчезает сразу, программа завершается только после того, как ввод записан на диск (с пределом ожидания). Снимает ограничение 2.4 «запись при закрытии окна уходит, но окно не ждёт ответа». Независимые ревью кода и безопасности — за оркестратором.

## Как устроено
1. **Ядро** (`src-tauri/src/windows/closing.rs`), `CloseRequested` окна хранилища:
   размер и положение окна запоминаются (`remember_placement`, до скрытия) → `prevent_close` → `hide` → событие `window:close-requested` **только этому окну** → поток ждёт ответа:
   - `window_close_ready` — окно уничтожается (`destroy`); из цикла закрытия окно выводит событие `Destroyed`;
   - `window_close_cancel` — окно показывается снова и получает фокус;
   - нет ответа за `CLOSE_TIMEOUT` = 10 с — окно уничтожается, в stderr строка без имён и текста заметок.
   Повторный `CloseRequested` во время ожидания — снова `prevent_close`, второго цикла нет. Окно без хранилища (управление хранилищами) закрывается сразу. Не удалось создать поток ожидания — окно уничтожается сразу (как до задачи), а не висит скрытым.
2. **Выход**: последнее окно уничтожается только после ответа (или предела), поэтому Tauri просит выхода, когда ждать уже нечего. Если выход попросили явно (`AppHandle::exit`), пока окна записывают, — `ExitRequested` откладывается (`exit_must_wait`), поток ждёт конца всех закрытий (предел + 2 с) и повторяет выход. Временная папка движка удаляется на `Exit`, как раньше.
3. **Интерфейс**: `Shell.svelte` подписывается на событие первым делом (до загрузки окна); `WindowClosing` (`src/shell/closing.ts`) вызывает `flushForClose` редактора (`src/editor/sessions.ts`) — запись всех заметок окна и ожидание ответов, включая записи, ушедшие раньше, повторы после `renamed` и конфликты. Заметка в состоянии «файла нет на диске» (`missing`) ждёт сигнала о переименовании до 1,5 с. Итог:
   - всё записано — `window_close_ready`;
   - что-то не записано — `window_close_cancel` + уведомление «Окно не закрыто: не удалось сохранить заметку «…». <причина> Текст остаётся в редакторе. Чтобы закрыть окно без сохранения, закройте его ещё раз в течение минуты.»; повторное закрытие в течение минуты — `window_close_ready` (иначе окно с хранилищем на вынутой флешке не закрыть никогда).
   `pagehide`/`beforeunload`/скрытие окна — оставлены запасным путём.

## Изменения контракта (расширение v1, прежнее не менялось)
- Событие `window:close-requested`, данные — пустой объект (`WindowCloseRequestedPayload {}`, `deny_unknown_fields`); `EVENT_NAMES` — 7 событий; снимок `contracts/v1/event.window.close-requested.snap`; фильтр isolation `CORE_EVENTS`; тест сверки `filter.test.ts`.
- Команды `window_close_ready`, `window_close_cancel`: без параметров, ответ `null`, ошибок нет; действуют только на окно вызова и только пока оно ждёт ответа. `commands/list.rs`, `capabilities/main.json` (окнам `vault-*`), `permissions/autogenerated/`, снимки, `OWN_COMMANDS` isolation, `src/api/`.
- Тестовая сборка (`webdriver`): `RHIZOMIND_E2E_SLOW_WRITE_MS` — пауза перед каждой `note_write`; строки нет в выпускном файле (`release-binary.test.ts`).

## Самопроверка безопасности
- Инвариант 1: сети нет; новых крейтов и пакетов нет.
- Инвариант 2: новых записей вне хранилища нет; размер окна пишется в `vaults.json`, как раньше.
- Инвариант 3: событие без данных; строка журнала без имён и текста заметок.
- Инвариант 4: закрытие окна больше не теряет ввод; при сбое записи окно не закрывается молча.
- Права: две новые команды не принимают параметров и не дают окну действовать на чужие окна (окно — по метке вызова; тест `answers_act_only_on_own_waiting_window`); окно может «закрыть себя» только в ответ на запрос закрытия от ОС. Прав `core:window:*` интерфейс по-прежнему не получает.

## Известные ограничения
- Пока окно скрыто и ждёт записи (обычно доли секунды, не дольше 10 с), его хранилище считается открытым: повторное открытие того же хранилища в это время даёт «фокус» на скрытое окно (ничего не видно). Повтор через мгновение работает.
- Предел 10 с: на очень медленном сетевом диске запись, идущая дольше, прерывается выходом программы.

## Вопросы владельцу
1. **Сбой записи при закрытии**: сделано «окно возвращается с уведомлением; повторное закрытие в течение минуты — без сохранения». Варианты: (а) так, как сделано (рекомендация — данные не теряются молча, выход из ситуации есть); (б) системное окно «Не удалось сохранить … Закрыть без сохранения? / Отмена»; (в) всегда закрывать (текст теряется).
2. **Предел ожидания**: 10 с. Оставить или изменить (5 / 30 с)?
