# Проверка задачи 0.2-4.5 (QA и ревью безопасности, 03.11.2026)

Принято: QA (208536f), ревью безопасности (208536f), повторная проверка QA+безопасность (144da7f), финальная (86ffd33, CI 41561357085).

## Исправлено до слияния
- Заметка, поправленная пользователем между сбоем и доделкой, переписывалась второй раз и уводила ссылку не туда. В отметке — хэши прочитанного и нового текста; ни тот ни другой → `failed` без повтора.
- Журнал переписывался целиком перед каждой заметкой (квадратичный объём). Заголовок + дописываемые отметки; 10 000 заметок — журнал 3,48 МБ, 28,9 с в отладочной сборке (с записью заметок).
- Файл заменён, но версию прочитать не удалось (антивирус) → заметка считается записанной, не повторяется.
- `open_service_append`: `O_NOFOLLOW`, проверка одного имени файла по дескриптору (жёсткие ссылки), проверка пути по дескриптору.

## Решения оркестратора
- Р20 (спецификация): причина `conflict` без повтора — для несопоставленных переименований и заметок, изменённых до доделки. До 0.2-4.6 отдаются как `io` без `retry_token`.

## Для 4.6
- `resume_on_open(&vault, &Links::new(vault.notes()?), &mut progress)` — после сверки индекса, до любого `run`; `Some(report)` → `links:updated` (`reason: resumed`), `note:changed` для `report.updated`, перечитать эти заметки в индекс.
- Планы — строго по очереди: журнал на хранилище один; `run` перезаписывает чужой незавершённый журнал.
- Ввести `conflict` в контракт (Р20).

## Отложенное
- Подменённый журнал на 31 МБ поднимает память до ~190 МБ (ограничено пределом 32 МБ).
- Окно «падение до второй отметки „начата“ после внешней правки» → `io` без повтора (осторожно, данные целы).
- У записанной заметки с непрочитанной версией `modified_ms = 0`.
