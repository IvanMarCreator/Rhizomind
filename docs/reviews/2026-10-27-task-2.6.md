# Задача 2.6 «Редактор, шаг 3: вики-ссылки» — отчёт разработчика (27.10.2026)

Ветка `task/2.6-wiki-links` от main 1567c9d. Ревью кода и безопасности — за другими агентами (раздел «Что проверить на ревью»).

## Сделано
- **Отображение (С3.4, вид 5Б)** — `src/editor/wikilinks/display.ts` (`wikiPieces`), вызывается из `link()` в `src/editor/live-preview/markdown.ts`. `[[Альфа/Встреча]]`, `[[/Встреча]]` → «Встреча»; `[[Встреча#Итоги]]` → «Встреча › Итоги» (значок `wiki-heading` вместо `#`); `[[…|псевдоним]]` → псевдоним; `.md` в конце и пробелы внутри скобок не видны. На строке с курсором разметка приглушена, как у остального Markdown. Недопустимая цель (`parseTarget` из `src/core/wikilinks`) и встраивание `![[…]]` — обычный текст.
- **Линейный разбор**: пары `[[` → `]]` ищутся одним проходом по строке (`wikiPairs`), по правилам `findWikilinks` (открывает последняя `[[` перед первой `]]`); код в строке внутри ссылки — не ссылка (`codeStartsIn` на общих поисках `nextOf`/`closingRun`). Прежний `indexOf(']]')` от каждой `[[` был квадратичным на `[[a[[a…`. Тест совпадения с `findWikilinks`: однострочные образцы `text.json` и 3000 случайных строк (`display.test.ts`). В `perf.test.ts` — 8 неудобных строк с `[[`.
- **Неразрешённые** — `resolve.ts` (поле ответов) и `resolverPlugin` в `live-preview/index.ts`: ключи видимой части (`wikiKeys`) уходят в `links_resolve` через 150 мс после ввода/прокрутки; до ответа ссылка выглядит разрешённой; по `vault:changed` (`Editor.svelte`) — спрашивается заново, прежний вид держится до ответа. Класс `cm-rz-wikilink-unresolved` (`--link-unresolved`, без подчёркивания).
- **Щелчок (решение 76)**: вне строки с курсором — обычный, на ней — Ctrl+щелчок; в режиме исходного текста — Ctrl+щелчок (`sourceLinks`, ссылка под указателем — `linkAt` по разбору строки, блоки кода — разбором оград до строки). Одинаково для `[текст](адрес)` (в исходном тексте раньше не открывались) и `[[…]]`. Вики-ссылка идёт в `WikiHost.open`, никогда в `open_external`.
- **Переход** — `open.ts` (`followWikilink`) и `window-host.ts` (`WindowWikiHost`): `links_resolve` → заметка открывается через `WindowModel.open` (шаг истории); `#Заголовок` — курсор на заголовок после открытия (`reveal.ts`, `findHeading`); ссылка на заголовок своей же заметки — переход без переоткрытия. Неразрешённая — `note_create` в папке заметки со ссылкой; с путём — от корня, недостающие папки `folder_create`, существующая папка в другом регистре — по `tree_list` (решение 84). Ошибка ядра — уведомление «Не удалось открыть ссылку. …».
- **Автодополнение** — `autocomplete.ts`, своё (без `@codemirror/autocomplete`, по решению 75): после `[[` список `links_suggest` (кратчайший различающий путь считает ядро), ↑/↓, Enter/Tab, щелчок, Esc; `]]` не удваиваются; «нельзя сослаться» — помечено, не вставляется; в заметке только для чтения не открывается. Работает в обоих режимах.
- **Стили** — `wikilinks.css` (импорт из `codemirror.ts`), не `EditorView.theme`: CSP окна запрещает `<style>` (находка Н7). `NoteText.svelte` не менялся по стилям. Список подсказок — `tooltips({ position: 'absolute' })` и `.cm-editor { position: relative }` в `wikilinks.css` (правило из базовых стилей CodeMirror, которые не действуют, Н7): без него сценарный тест показал список у левого края окна. **Для 2.10**: если базовые стили редактора вернутся, это правило можно убрать оттуда.
- **Контракт v1 и ядро не менялись**: новых команд, прав окна и пакетов нет; Rust не тронут.

## Что проверить на ревью
- Совпадение разбора предпросмотра с `findWikilinks` вне однострочных образцов: многострочный код в строке (пара обратных апострофов через перенос внутри абзаца) — предпросмотр разбирает строку отдельно (как и прежде для выделения).
- `\[[…]]` — в предпросмотре экранирование `\[` делает текст обычным, `findWikilinks` экранирование не знает (образцы общих правил его не задают).
- Безопасность: `open.test.ts` «недопустимая цель — ни одного вызова ядра»; вики-ссылка не вызывает `open_external` (`Wikilinks.component.test.ts`).
