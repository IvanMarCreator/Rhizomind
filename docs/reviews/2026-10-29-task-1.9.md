# Задача 1.9 «Переименование с правкой» — что сделано и что отложено (29.10.2026)

Ветка `task/1.9-rename-with-edit` от main 4b647d7. Решение владельца 89: файл открытой заметки снаружи переименован (перенесён) и изменён в одну склейку событий — если это тот же файл, ядро распознаёт переименование, заметка остаётся открытой под новым именем, изменение подхватывается как внешняя правка (С3.6); файл, записанный заново, — удаление и создание. Инвариант 4.

## Как устроено

| Что | Как | Где |
|---|---|---|
| «Тот же файл» | Тот же идентификатор (NTFS FileId, inode) и тот же вид элемента, плюс **прежние размер и дата изменения** (как раньше) **или одна и та же дата создания**, известная с обеих сторон (`Node::same_file`). Новый файл с освободившимся идентификатором (inode Linux, FAT/exFAT) получает новую дату создания — защита ADR 0006 от повторно выданного inode сохраняется. Без даты создания (NFS и т. п.) — прежнее правило | `src-tauri/src/watcher/tree.rs` (`Node::born`, `same_file`, `Origins::find`) |
| Источник даты создания | Без новых вызовов ОС: Windows — поле `CreationTime` того же ответа `FileIdExtdDirectoryInfo`; Linux — `statx` из `DirEntry::metadata` (`STATX_BTIME`); macOS — `st_birthtime`. Нулевая или до 1970 года — неизвестна | `listing_windows.rs` (`Entry::created`), `tree.rs` (`read_node`, `birth`) |
| Итог для окна | `Renamed` + `Modified` нового пути → `note:renamed`, затем `note:changed` с версией с диска; интерфейс (2.9) переводит сессию на новый путь и обрабатывает правку как внешнюю: без ввода — текст с диска, с вводом — обе версии | `tree.rs` (`resolve`), `events/mod.rs` (без изменений) |
| Внутри переименованной папки | Файл с тем же идентификатором и датой создания, изменённый в ту же склейку, — часть переименования папки и `Modified`, а не «исчез» + «появился» | `absorb_content`, `folder_confirmed` |
| Через отложенное «исчез» (0,6 с) | Старый путь пришёл одной пачкой, новый — следующей, файл уже изменён: то же правило при сопоставлении с отложенным | без изменений в `mod.rs` |
| Вид элемента | **Не ослаблен** (замечание QA 2.9): заметка ↔ не-заметка переименованием не считается. Emacs/Vim (`Заметка.md` → `Заметка.md~`, новая `Заметка.md`) — только `Modified` заметки | `Origins::find` (`same_kind`) |
| Своя запись | Правка по новому пути переименования сверяется с журналом своих записей так же, как обычная правка | `resolve` (`own.is_own`) |

## Отложено и найдено

| Что | Почему | Предложение |
|---|---|---|
| **Найдено (было до 1.9, Linux):** `notify-debouncer-full` 0.8.0-rc.2 теряет путь источника переименования, если в ту же склейку на новый путь положили другой файл (`mv a.md b.md`, затем замена `b.md` через временный файл; или `mv a b; rm b`). В склеенных событиях есть только `Remove b`/`Create b`, `a.md` в сверку не попадает и остаётся в модели и дереве до полной сверки; открытая `a.md` не закрывается, её запись получает `not_found` («нет файла», ввод держится) | В `push_rename_event`/`push_remove_event` склейки очередь нового пути заменяется, и событие `Rename(a, b)` в ней пропадает. Windows не затронут (`ReadDirectoryChangesW` даёт `From`/`To` без связи, очередь `a` остаётся). Потери ввода нет | Отдельная задача ядра: обёртка над `RecommendedWatcher` (свой тип `Watcher` для `new_debouncer_opt`), которая запоминает пути источников переименований из сырых событий и добавляет их в пачку склейки. Без новых крейтов. Тест модели уже есть (`renamed_and_rewritten_as_a_new_file…`); сценарий наблюдателя в `watcher_tests` взят «Сохранить как + удалить старый» |
| Туннелирование имён (NTFS, FAT): переименование в имя, удалённое в той же папке меньше 15 с назад, подставляет дату создания удалённого | Тогда переименование с правкой видно как «исчез» + «появился» — как до 1.9. Редкое сочетание | Не делать; при необходимости — доверять одному FileId для идентификаторов из `FileIdExtdDirectoryInfo` (NTFS/ReFS — с номером последовательности, повторно не выдаются) |
| Файловые системы без даты создания (NFS, часть сетевых) | Правило прежнее: переименование с правкой — «исчез» + «появился» | Не делать |

## Что проверить владельцу руками (Windows)

1. Открыть заметку, в Проводнике переименовать её файл и сразу (в пределах полсекунды) дописать строку из Блокнота, сохранив поверх нового имени — проще всего скриптом PowerShell: `Rename-Item 'A.md' 'B.md'; Add-Content 'B.md' 'снаружи'`. Ожидается: заметка открыта под именем «B», строка «снаружи» видна в редакторе, уведомления об удалении нет.
2. То же, но перед этим набрать в заметке текст и не ждать секунду: ожидается уведомление «Сохранены обе версии», ваш текст — в «B», версия с диска — в копии «B (внешняя версия …).md».
3. То же с переносом в другую папку: `Move-Item 'A.md' 'Архив\B.md'; Add-Content 'Архив\B.md' 'снаружи'`.
4. Сохранение внешним редактором не закрывает заметку: открыть заметку в Rhizomind и в Notepad++/VS Code, сохранить там — заметка обновилась, не закрылась.
