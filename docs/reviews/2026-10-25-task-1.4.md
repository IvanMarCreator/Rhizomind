Сигналы наблюдателя — `watcher::WatcherEvent` (`Changed(VaultChangedPayload)`, `Unavailable`, `Available`, `DeliveryFailed`); типы контракта в `commands/` не менялись. Решение, что делать с открытыми заметками при `Unavailable`, — за 1.7.

Отступление от ADR 0006 (запасной путь переноса — размер и дата вместо хэша: хэш удалённого файла недоступен без хранения хэшей всех файлов) оркестратор записывает в ADR.

## В задачу 1.7 «Команды ядра на настоящих модулях»

- **Один журнал своих записей** в нейтральном модуле: общий `Arc` у `Vault` и `VaultWatcher` (сейчас `OwnWrites` в `watcher/`, связывается через `VaultWatcher::own_writes()` / `start_with`). Ключ — по написанию имени с диска и по ключу имени (`names::key`): на Windows хранилище может получить путь в другом регистре.
- **События `vault:changed` идемпотентны** для интерфейса: `Renamed` с отсутствующим `from` игнорируется, `Created` существующего — не ошибка (наблюдатель выдаёт точный порядок, но пачки после `rescan` и гонки с собственными командами возможны).
- **Конфликт решается только сравнением хэша** версии на диске с ожидаемой (`note_write`), а не по событию наблюдателя.
- **Замер `VaultWatcher::start`** на 10 000 и 50 000 файлов на Windows (обход и `file-id` на каждый файл); первичный обход — вне открытия окна (не блокировать интерфейс).
- **`get_file_id` с `FILE_FLAG_OPEN_REPARSE_POINT`**: сейчас ссылки отсеиваются до вызова по типу записи каталога, но открытие без этого флага переходит по точке повторной обработки.
- **Флаг отмены долгой сверки** (закрытие хранилища во время полного обхода большой папки — `Drop` ждёт конца сверки).
- **Заглушки OneDrive** (файлы «только в облаке»): обход читает метаданные и `file-id`, хэш считается только для своих записей; проверить, что слежение не вызывает загрузку файлов.
