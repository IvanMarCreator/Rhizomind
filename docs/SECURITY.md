# Модель безопасности Rhizomind (Secure-редакция)

Документ для службы информационной безопасности. Каждая мера ссылается на файл, где она реализована, чтобы её можно было проверить в коде. Документ обновляется вместе с каждым выпуском; выпуск не считается готовым, пока его меры не внесены сюда.

> **Состояние.** Платформа — Tauri 2: ядро на Rust, интерфейс в системном WebView2 ([ADR 0008](adr/0008-platform-tauri2.md)). Код выпуска 0.1 пишется по задачам плана. Пометка **«реализовано»** — мера есть в коде, рядом ссылка на файл и тест; пометка «выпуск 0.1, ADR …» — мера ещё в работе, указан файл, где она будет. Каркас приложения (задача 0.2) реализовал проверки цепочки поставок, CSP, `freezePrototype`, права окна и режим установщика; защищённая оболочка WebView2 (задача 0.3) — InPrivate, временную папку данных с удалением, флаги движка, удаление `WEBVIEW2_*`, SmartScreen, правку wry против отправки дампов, isolation pattern, запрет переходов, окон, загрузок и разрешений. Прототип `prototype/` и ветка `archive/electron-skeleton` (Electron) — справочные, их меры к выпуску не относятся. Целевые требования — в [product/requirements.md](product/requirements.md#безопасность).

## Ключевые гарантии

1. **В коде приложения нет сети.** Ядро на Rust не содержит сетевых библиотек — это проверяется автоматически при каждой сборке (`cargo deny check`, `cargo tree`). Нет синхронизации, облака, телеметрии, автообновлений, загрузки внешних ресурсов, встроенного браузера и плагинов. Внешняя ссылка открывается в системном браузере только после подтверждения пользователя.
2. **Данные в хранилище, локальные записи учтены.** Заметки — обычные `.md`-файлы в папке, которую выбрал пользователь; служебные данные хранилища — в `.rhizomind/` внутри неё. Имена и содержимое заметок вне хранилища не пишутся. Прочие записи приложения и браузерного движка на этом компьютере вне хранилища допускаются только локально — не в сеть и не в синхронизируемые места (OneDrive, перемещаемый профиль Windows) — и каждая перечислена в разделе «Записи вне хранилища» ниже. Автоматическая проверка следов в CI ловит новые неучтённые записи.
3. **Браузерный движок ничего не сохраняет.** WebView2 работает в режиме InPrivate; его служебная папка — во временной папке ОС и удаляется после выхода. Дампы падений в Microsoft не отправляются (при падении процесса движка WebView2 пишет дамп локально во временную папку — она удаляется вместе со всем остальным, см. «Хранение и следы»).
4. **Изоляция интерфейса.** Интерфейс не имеет доступа к файловой системе и сети. Он может только вызывать явно разрешённый набор команд ядра над открытым хранилищем.
5. **Без потери данных.** Приложение не затирает изменения файлов, сделанные снаружи. Удаление — только в корзину ОС.

### Честно о WebView2
WebView2 — компонент Windows (движок Microsoft Edge), на котором работают, например, новые Outlook и Teams. Rhizomind использует **системную версию WebView2 (Evergreen)**, которую обновляют Microsoft или служба ИТ ([ADR 0007](adr/0007-webview2-traces-network.md)).
- Все сетевые функции WebView2, которые может выключить приложение, выключены (таблица «Сеть WebView2» ниже).
- **Обязательные диагностические данные WebView2** отправляются в Microsoft всегда; необязательные — по настройке диагностики Windows. Это поведение компонента Windows, приложение его отключить не может. Содержимое заметок в этих данных приложением не передаётся.
- **Experimentation and Configuration Service:** WebView2 получает конфигурацию с серверов Microsoft (на неуправляемом ПК — и эксперименты). Полностью отключается политикой Windows `ExperimentationAndConfigurationServiceControl = 0` (раздел реестра политик Microsoft Edge WebView2), которую выставляет служба ИТ.
- **Можно отказаться от этих обращений**, если поставлять с приложением встроенную фиксированную версию WebView2: тогда служба ИТ ставит на путь движка правило брандмауэра «запретить исходящие», не задевая Teams и Outlook. Недостатки: установщик больше примерно на 180 МБ; обновления движка выпускаем мы, каждое — новый выпуск и, вероятно, повторное согласование; на Windows 10 при установке нужны права на папку движка (`icacls`); с сетевого диска не запускается. Этот вариант не разрабатывается; к нему вернёмся, только если ИБ отклонит выпуск из-за обращений WebView2 к Microsoft.

#### Разобранные исключения проверки сети

Решение владельца 52 (спецификация 0.1, раздел 12). Проверка находит в собранном интерфейсе места, где код CodeMirror обращается к глобальному объекту без свойства (`defaultView || window`, выбор `globalThis`) и к `Function`. Сетевых вызовов там нет; каждое место разобрано глазами и внесено в список [tools/check-no-network/allowlist.json](../tools/check-no-network/allowlist.json) — там же полная причина, кто и когда разобрал. Как работает сопоставление ([allowlist.ts](../tools/check-no-network/allowlist.ts)):

- **Разрешимы ровно три вида находок** (закрытый список `ALLOWED_KINDS`): «глобальный объект window без свойства», «глобальный объект globalThis без свойства» и «Function справа от instanceof» (`x instanceof Function`; любое другое употребление `Function` — обычная находка «Function»). Всё остальное исключением не разрешается ни при каких записях: сетевые вызовы (`fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, `window.open`, присваивание `location` и др.), `eval`/`Function`, `import()`/`require()` с вычисляемым именем, `Image`/`Audio`, таймеры со строкой, `createElement` опасных элементов, обращения по вычисляемому имени к `window`, `navigator`, `X.defaultView`, `X.win`. Запись с другим видом не принимается при чтении списка.
- `npm run check:network` собирает интерфейс дважды: `dist/` — как в выпуск, без карт исходников, и копию `.network-check/dist/` с картами (`vite build --sourcemap hidden`). Каждый файл `dist/` должен совпасть с копией байт в байт, иначе проверка красная; карты в выпуск не попадают.
- Для находки в `dist/` по карте ищется исходная строка — только при точном совпадении позиции. Исходный файл разбирается заново: на месте, куда указала карта (строка и столбец), должна быть находка того же вида, иначе красное.
- Исходник проверяется по настоящему пути (`realpath`): если он не в `node_modules` проекта (в том числе ссылка или junction из `node_modules` в `src/`), это наш код — исключение не действует. Находки в `src/` и `src-isolation/` исключениями не разрешаются никогда.
- **Только пакет верхнего уровня** `node_modules/<имя>`: вложенная копия (`node_modules/a/node_modules/<имя>`) не может выдать себя за разрешённый пакет. Запись пакета в `package-lock.json` обязана иметь `integrity` (sha512) и не иметь `inBundle`/`link`; установленная версия обязана совпадать с lock.
- Запись совпадает только по всем полям: пакет, версия из `package-lock.json`, файл в пакете, **SHA-256 всего файла** (правка в любом месте файла делает все его записи недействительными), номер строки, SHA-256 текста строки, вид находки; каждая запись покрывает ровно `count` находок. Новая версия пакета, изменённая строка или файл — исключение недействительно, проверка красная с сообщением «разберите заново». Неиспользованная запись — тоже ошибка.
- Список исключений подтверждён ревьюером безопасности 2026-10-26 (повторное ревью 1d2e40c); отметка — в поле `reviewedBy` каждой записи.

## Политики для службы ИТ

Приложение закрывает всё, что может закрыть само. Остальное — настройки Windows, которые выставляет служба ИТ (групповые политики или реестр):

| Что | Политика | Зачем |
|---|---|---|
| Сервис конфигурации и экспериментов WebView2 | `ExperimentationAndConfigurationServiceControl = 0` (политики Microsoft Edge WebView2) | WebView2 не получает конфигурацию и эксперименты с серверов Microsoft |
| Диагностические данные Windows | уровень «Обязательные» или ниже; на Enterprise — «Безопасность» (`AllowTelemetry = 0`) | обязательная диагностика WebView2 — компонент Windows |
| Отчёты Windows об ошибках (WER) | `Disable Windows Error Reporting` (`HKLM\SOFTWARE\Policies\Microsoft\Windows\Windows Error Reporting\Disabled = 1`) или исключение приложения (`ExcludedApplications`, `rhizomind.exe`); не включать `LocalDumps` для `rhizomind.exe` и `msedgewebview2.exe` | дамп памяти процесса может содержать текст заметок; приложение ограничивает WER для себя (`SetErrorMode`, `WerSetFlags`), но `__fastfail` и системные сбои обходят эти настройки |
| Переменные `WEBVIEW2_*` и ключи реестра WebView2 | приложение удаляет переменные у себя; ключи реестра `...\Policies\Microsoft\Edge\WebView2\` (`AdditionalBrowserArguments`, `UserDataFolder`, `BrowserExecutableFolder`) — только у службы ИТ, приложение их не читает и не пишет | ключи реестра WebView2 применяет сам загрузчик движка — значит, ими же служба ИТ может ужесточить настройки |

## Как проверить самостоятельно

- **Сетевой монитор** (Wireshark или брандмауэр Windows с журналом): запустить приложение, пройти обычную работу. Процесс `rhizomind.exe` не устанавливает соединений; запущенные им процессы `msedgewebview2.exe` обращаются только к службам Microsoft, описанным выше.
- **Process Monitor** (фильтр по `rhizomind.exe` и дочерним `msedgewebview2.exe`): вне хранилища запись только в места из раздела «Записи вне хранилища» (`%LOCALAPPDATA%\Rhizomind\vaults.json` и его временный файл при записи, временная папка `rhizomind-*` и учтённые там следы); после выхода временной папки нет.
- **Командная строка движка** (Process Explorer или `Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'"`): у процесса браузера — `--user-data-dir="%TEMP%\rhizomind-webview-…\EBWebView"`, `--edge-webview-disable-crash-reporting=1`, флаги из таблицы «Сеть WebView2», нет `--remote-debugging-port`.
- **`cargo deny check`** в папке `src-tauri/`: проверка лицензий, запрещённых сетевых крейтов и функций.
- **`cargo tree -e normal --target x86_64-pc-windows-msvc`** (и для других целей): в выводе нет `reqwest`, `hyper`, `h2`, `rustls`, `native-tls`, `openssl`, `socket2`, `tungstenite`.
- Прочитать файлы из таблиц выше: весь код открыт.

## Известные ограничения

- **Linux и macOS: решение 66 до перехода на эти ОС выполнено не полностью.** Признак «хранилище на внешнем носителе стало недоступно» там — только «папки хранилища нет» (`storage_lost` в [vault/fsops.rs](../src-tauri/src/vault/fsops.rs)): типа тома, как `DRIVE_FIXED` на Windows, нет. Поэтому если папку хранилища на внутреннем диске переименовали или удалили снаружи и запись при закрытии окна не удалась, окно закрывается с сообщением, и несохранённый ввод теряется (на Windows окно вернулось бы). Вариант исправления — сравнивать устройство папки хранилища (`st_dev`) с устройством её родителя или корня ФС. Сейчас программа выпускается для Windows.

- **Выход из системы и выключение Windows во время несохранённого ввода.** При завершении сеанса Windows библиотека окон (tao) завершает процесс сразу, без запроса закрытия окна (`CloseRequested`): ожидание записи (задача 0.7) не срабатывает, ввод последней секунды (до автосохранения) может не записаться. Задача после КТ1: обработать `WM_QUERYENDSESSION` и задержать завершение сеанса через `ShutdownBlockReasonCreate`, пока ввод не записан.

- **Проверка сети неполна для косвенных путей к объекту окна.** Статическая проверка интерфейса (`tools/check-no-network/`) не видит косвенное получение окна: деструктуризацию `{ win }` / `{ defaultView }`, `Reflect.get`, `window.self` / `top` / `parent` / `globalThis.window`. Сетевые запросы, собранные таким путём, в рабочем приложении блокирует политика контента (CSP `connect-src ipc: http://ipc.localhost`, сценарный тест в [tests/e2e/secure-shell.test.ts](../tests/e2e/secure-shell.test.ts)); закрытие пробела в статической проверке — отдельная задача.
- **Обработчик протокола через `cmd /c`.** Адрес уходит в ОС только из символов RFC 3986, но `&` среди них допустим (разделитель параметров в адресе). Если в системе обработчик протокола `http`/`https`/`mailto` зарегистрирован командой вида `cmd /c … "%1"`, знак `&` из адреса может разделить команды этой оболочки. Rhizomind на регистрацию обработчиков не влияет: это настройка системы (ИТ-политика); стандартные обработчики браузеров и почтовых программ запускаются напрямую, без `cmd` (ревью 1.5, п. 3).
- Сборки пока не подписаны цифровой подписью: Windows показывает предупреждение SmartScreen при запуске установщика. Для корпоративного распространения нужна подпись кода (Windows Authenticode, Apple Developer ID).
- Заметки хранятся без шифрования: защита данных на диске обеспечивается средствами ОС (BitLocker, FileVault, LUKS). Шифрование появится только по требованию ИБ.
- WebView2 — компонент Windows: его обновления и обязательная диагностика управляются Microsoft и службой ИТ, а не приложением (см. «Честно о WebView2»).
- При падении процесса WebView2 его дамп пишется локально во временную папку движка (отключить нельзя); не отправляется и удаляется после выхода или при следующем запуске. Пока приложение работает после такого падения, дамп лежит в `%TEMP%`.
- Действие флагов Chromium против фоновой сети для WebView2 не документировано: они заявлены, но гарантией станут после сетевого аудита (задача 3.3).
- Установка NSIS для текущего пользователя кладёт файлы программы в `%LOCALAPPDATA%\Programs\Rhizomind`: это исполняемые файлы, а не данные приложения.
- macOS и Linux: меры для WKWebView и WebKitGTK проверяются при переходе на эти ОС.
- **Движок WebView2 обращается к брокеру токенов Windows (WAM)** через свою библиотеку OneAuth; при первом запуске под пользователем это вызывает выход службы Windows `wlidsvc` в сеть к службе входа Microsoft и запись кэша в `%LOCALAPPDATA%\Microsoft\TokenBroker\Cache\`. Приложение и процессы движка сами в сеть не выходят (задача 0.6, [docs/research/2026-10-26-traces-investigation.md](research/2026-10-26-traces-investigation.md)). OneAuth загружается в момент штатного закрытия окна. **Мера (решение владельца 64, задача 0.7):** при закрытии последнего окна программы ядро сначала дожидается записи ввода, затем завершает процесс браузера WebView2 (`TerminateProcess`; **дескриптор процесса браузера держится с создания окна**: открывается сразу по `BrowserProcessId` с проверкой «процесс жив» и имени образа `msedgewebview2.exe` (`QueryFullProcessImageNameW`), завершение и ожидание при выходе — только через него, поэтому номер упавшего браузера, доставшийся чужому процессу, ничего не завершит; ревью 0.7, B3), затем уничтожает окно и удаляет временную папку движка — OneAuth не загружается, `.tbres` не пишется, `wlidsvc` в сеть не выходит (опыт 0.6б на зонде wry: 4 из 4 запусков и 2 чистые машины из 2). Закрытие не последнего окна идёт штатно: один процесс браузера обслуживает все окна. После завершения браузера новые окна не создаются (повторный запуск в эти доли секунды ничего не открывает). Побочные следы: дампов падения нет; движок пишет в принятый ключ `HKCU\Software\Microsoft\EdgeWebView\StabilityMetrics` (решение 61) значение `exited_cleanly = 0` вместо `1`. Реализация — `destroy`, `is_last_window`, `is_exiting` в [src-tauri/src/windows/closing.rs](../src-tauri/src/windows/closing.rs), `BrowserProcess` в [webview_traces/process.rs](../src-tauri/src/webview_traces/process.rs) (тесты `only_webview2_browser_image_is_accepted`, `foreign_process_is_not_taken_as_browser`), `WebviewDataDir::set_browser_pid` в [webview_traces/mod.rs](../src-tauri/src/webview_traces/mod.rs); тесты — `last_window_*` в [windows/tests.rs](../src-tauri/src/windows/tests.rs), сценарный тест на Windows [tests/e2e/browser-exit.test.ts](../tests/e2e/browser-exit.test.ts) (наблюдатель модулей процесса браузера: `oneauth.dll` не загружена; контрольный прогон со штатным закрытием — загружена; новых отчётов WER/дампов нет; временная папка удалена); тест следов [traces.test.ts](../tests/e2e/traces.test.ts) валит появление после выхода выпускной сборки любого файла в `TokenBroker\Cache`, кроме файла фонового задания Windows (задача 0.6в); полная проверка — задание `oneauth-kill-first` ([tools/traces-investigation/](../tools/traces-investigation/)). Ограничения: выход из системы и выключение Windows, аварийное завершение программы, закрытие через «Диспетчер задач» обходят меру; поведение может измениться с обновлением WebView2. **Дополнительная мера ИТ** (не зависит от приложения): служба `wlidsvc` («Помощник по входу в учётную запись Майкрософт») выключена или политика «Учётные записи: блокировать учётные записи Майкрософт». Файл в `%LOCALAPPDATA%\Microsoft\Credentials\`, который видел тест следов, — запись Windows, не Rhizomind (там же).
- **Политика WebView2 `AdditionalBrowserArguments`** (`HKLM`/`HKCU\Software\Policies\Microsoft\Edge\WebView2`) добавляет флаги движку Rhizomind мимо очистки переменных `WEBVIEW2_*` (проверено в задаче 0.6: функции дописываются к `--disable-features` приложения). Писать туда может только администратор — это канал службы ИТ.
- **Окно выбора папки (Windows) на доли секунды держит путь к хранилищу в `ComDlg32\LastVisitedPidlMRU`** (перемещаемый профиль): Windows создаёт запись при закрытии окна, Rhizomind сразу стирает её `ClearClientData`. Путь мог бы попасть в копию профиля, только если профиль выгружается на сервер именно в этот момент; остатки байтов в журналах куста (`NTUSER.DAT.LOG*`) не исследовались. ShellBags с путём остаются в локальной части профиля — см. «Записи вне хранилища».
- **Жёсткие ссылки (hard links).** Жёсткая ссылка — второе имя того же файла; ссылку внутри хранилища на файл вне его контуром не отличить: для ОС это обычный файл хранилища. Создать её может только тот, у кого уже есть право записи в обе папки (тот же пользователь или администратор). Rhizomind жёстких ссылок не создаёт; запись через замену файла (`ReplaceFileW`, `rename`) разрывает связь и меняет только имя внутри хранилища, исходный файл вне хранилища не изменяется.
- **Гонка «проверил — открыл».** По дескриптору проверяются открываемые файлы и папки (см. «Файлы»), но сами действия — замена файла (`ReplaceFileW`, `rename`), **создание** файла или папки, переименование, перемещение и удаление — выполняются по пути. Если в доли секунды между проверкой и действием процесс с правами пользователя подменит промежуточную папку ссылкой или точкой соединения, **файл может быть заменён, создан, переименован или удалён вне хранилища** (по ссылке). Это требует вредоносной программы, уже работающей от имени пользователя (ей контур не нужен — у неё и так есть доступ к его файлам). Закрытие — операции относительно удерживаемого дескриптора папки (`cap-std` или папки, открытые без `FILE_SHARE_DELETE`) — в задаче 1.7 не сделано (нужна новая зависимость или своя обёртка над `NtCreateFile` и перестройка всех операций `vault`), перенесено отдельной задачей (`docs/reviews/2026-10-25-task-1.7.md`).
- **Окно между сверкой версии и заменой.** Версия на диске сверяется второй раз непосредственно перед заменой; внешняя правка, сделанная в доли миллисекунды между этой сверкой и самой заменой, будет заменена текстом из редактора без копии. Блокировки файлов, общей для всех программ, в ОС нет.
- **Корзина Windows на несъёмном диске** (`DRIVE_FIXED`) с отключённой корзиной (свойство «Уничтожать файлы сразу») или для файла больше размера корзины: оболочка Windows может удалить файл безвозвратно, хотя ядро считает, что корзина есть. Требует ручной проверки на проверочной машине (аудит 3.3).
- **macOS:** проверка итогового пути по дескриптору пока заменена проверкой по пути (`canonicalize`); дата создания при записи не переносится.
- **Один экземпляр программы (задача 0.5) — ограничения механизма.** Данные хранилищ ни в одном случае не раскрываются; худшее — программа не запускается или окно не выводится вперёд.
  - Процесс того же пользователя может заранее занять имя мьютекса `Local\Rhizomind.SingleInstance`: Rhizomind тогда ~5 с пытается достучаться до «первого экземпляра» и выходит с сообщением «Rhizomind уже запущен».
  - Процесс того же пользователя может создать своё окно для сообщений с классом `Rhizomind.SingleInstance`: второй запуск отправит сигнал ему и выйдет (в сигнале нет данных — только метка протокола).
  - Первый экземпляр запущен от администратора: обычный запуск получает `ERROR_ACCESS_DENIED` на мьютекс (считается «уже запущен»), а UIPI не пропускает `WM_COPYDATA` к процессу с более высоким уровнем целостности — второй запуск выходит, окно первого вперёд не выводится.
  - Другой пользователь в том же сеансе (`runas`): пространство имён `Local\` у сеанса общее — его запуск считается вторым экземпляром.
  - Linux, macOS: второй запуск только выходит с сообщением в stderr, окно первого вперёд не выводится (канала связи между процессами нет — без сети, без D-Bus).
- **Linux:** дата создания заметки после записи может сдвинуться (замена через `rename`), поэтому «самая старая» из заметок с одним именем может смениться после правки (ADR 0006, уточнение 25.10.2026).



- **Окно безвозвратного удаления (диск без корзины) — кнопка по умолчанию «Удалить безвозвратно».** Системное окно `tauri-plugin-dialog`: Enter подтверждает удаление. Окно появляется только на дисках без корзины (флешка, сетевая папка); работа с такими дисками — исключение, риск принят владельцем (решение 55, 26.10.2026). - **Служебные записи движка WebView2 в перемещаемом разделе реестра (принято владельцем, решение 61).** При первом запуске движок Microsoft пишет в `HKCU\Software\Microsoft\EdgeWebView\…` (BLBeacon, PreferenceMACs, StabilityMetrics, UsageStatsInSample) и `HKCU\Software\Microsoft\EdgeUpdate\ClientState\{F3017226…}` (`lastrun`). Доказательство: [docs/research/2026-10-26-traces-investigation.md](research/2026-10-26-traces-investigation.md).
