# Ручной сетевой аудит и проверка Process Monitor (выпуск 0.1)

Для кого: владелец продукта, на **второй машине** (план 0.1, П4). Зачем: доказать для ИБ критерии приёмки 3 и 4 спецификации 0.1 (раздел 9) и подтвердить или снять с гарантий флаги движка против фоновой сети (ADR 0007, задача 3.3). Автотесты этого не заменяют: в CI нет «чистой» Windows без фоновых процессов раннера, а сеть раннера закрыта не так, как в компании.

Время: около полутора часов — час работы со скриптом (плюс минута на пробную запись Process Monitor) и 10–40 минут выгрузки журнала Process Monitor в CSV на шаге 10. Место: **20 ГБ свободно** на диске папки результатов — журнал всех событий машины за час занимает 5–20 ГБ, CSV при выгрузке — столько же (скрипт предупреждает, если места меньше). Результат: папка `C:\rhizomind-audit-<дата>` (не на рабочем столе: он часто синхронизируется OneDrive — скрипт откажется писать в OneDrive и в перемещаемый профиль); в чат — `results.md` и файлы `summary-*.csv`.

Скрипт проверен автоматически в CI на Windows (решение владельца 102): синтаксис Windows PowerShell 5.1, PSScriptAnalyzer, разбор журнала Process Monitor на образце ([tests/audit/](../../tests/audit/)), прогон без Process Monitor на выпускной сборке до `results.md`. Шаги с Process Monitor, журналом DNS и вопросами в CI не проходят — их впервые выполняет владелец.

## Как запустить

1. Скопируйте `network-audit.ps1` на вторую машину (например, на рабочий стол).
2. Распакуйте Rhizomind и Process Monitor в любые папки.
3. Закройте Process Monitor, если он открыт: скрипт запускает его сам и сам сбрасывает его настройки на время аудита (раздел «Process Monitor: настройки» ниже). Готовить ничего не нужно.
4. Откройте Windows PowerShell **от имени администратора** (не ISE) и выполните:
   ```powershell
   powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\network-audit.ps1" -AppExe "C:\Rhizomind\rhizomind.exe" -Procmon "C:\Tools\Procmon64.exe"
   ```
   Ключ `-ProcmonConfig` из прежней версии инструкции больше не нужен: если он остался в команде, скрипт его примет и не будет использовать.
   Пути замените своими; кавычки от «Копировать как путь» можно оставить. Если путь не указан, скрипт спросит; если файла нет — напишет «Файл не найден» и спросит снова; пустой ответ на вопрос о Process Monitor — предложение продолжить без него, о `rhizomind.exe` — выход.
5. Дальше скрипт ведёт сам: 11 шагов, на каждом — что сделать и Enter для продолжения. На вопросы «(д/н)» отвечайте `д` или `н` (принимаются и `да`/`нет`, `yes`/`n`, а также `l` — это «д» в английской раскладке; одиночное `y` не принимается — это «н» в английской раскладке); на другой ответ скрипт попросит ввести «д» или «н».
6. Перед шагом 4 Rhizomind должен быть закрыт: скрипт запускает его сам (программа однооконная по экземпляру — второй запуск передал бы команду открытому окну, и дерево процессов было бы чужим).

**Без прав администратора** — только опрос соединений, без Process Monitor (шаги 3 и 10 пропускаются):
```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\network-audit.ps1" -AppExe "C:\Rhizomind\rhizomind.exe" -NoProcmon
```
Без администратора, но с Process Monitor скрипт предупредит: Windows несколько раз спросит разрешение (UAC) — на пробную и основную запись (шаг 3), на остановку и выгрузку (шаг 10).

**Прервать** можно в любой момент: Ctrl+C или закрытие на ошибке. Скрипт в любом случае остановит Process Monitor (`/Terminate`), вернёт его настройки и журнал DNS в прежнее состояние и подскажет, если Rhizomind ещё запущен. **Не закрывайте окно PowerShell крестиком:** тогда скрипт ничего не успеет убрать — остановите Process Monitor сами командой `Procmon64.exe /Terminate` (из его папки, от администратора), верните его настройки: `reg import C:\rhizomind-audit-<дата>\procmon-settings-backup.reg` (если файла нет — настроек до аудита не было, ключ `HKCU\Software\Sysinternals\Process Monitor` можно удалить), а журнал DNS выключите: `wevtutil sl Microsoft-Windows-DNS-Client/Operational /e:false` (если до аудита он был выключен).

### Что скрипт оставляет на машине (честно)

Скрипт ничего не скачивает, в сеть не ходит и не удаляет файлов (`capture.pml`, `capture.csv`, `procmon-probe.*` удаляете вы после разбора); результаты пишет в свою папку. Вне её:
- **настройки Process Monitor** (реестр `HKCU\Software\Sysinternals\Process Monitor`: фильтр, столбцы, согласие с EULA и т. п.) на время аудита сбрасываются: перед шагом 3 ключ сохраняется в `procmon-settings-backup.reg` в папке результатов и удаляется, в ключ записывается только «не показывать имена вместо адресов» (`ResolveAddresses = 0`); в конце — и при сбое, и после Ctrl+C — ключ возвращается из копии как был (если его не было — удаляется). Пока идёт запись, Process Monitor сам пишет в этот ключ свои настройки, как всегда;
- **Process Monitor** ставит свой драйвер (служба `PROCMON24`, файл в `C:\Windows\System32\drivers`) — так он работает всегда;
- **журнал DNS** (если вы согласились его включить): события за время аудита остаются в системном журнале `Microsoft-Windows-DNS-Client/Operational`; его включённость скрипт возвращает как было, события не стирает;
- Windows PowerShell ведёт свои обычные журналы (история команд и т. п.).

### Process Monitor: настройки

Первый аудит (01.11.2026, решение 107а) дал журнал без единого события Rhizomind, кэша `TokenBroker` и `ConsentStore`, хотя сеть других процессов в нём была: Process Monitor записывал с настройками, сохранёнными на машине (фильтр, выключенные классы событий или правило «Drop Filtered Events» — отбрасывать отфильтрованное). Поэтому теперь скрипт не полагается на настройки машины:
1. **Сброс настроек.** Ключ `HKCU\Software\Sysinternals\Process Monitor` сохраняется в `procmon-settings-backup.reg` и удаляется — Process Monitor стартует с заводскими настройками: без фильтра и без «Drop Filtered Events», со всеми классами событий (файлы, реестр, сеть, процессы), без кольцевого буфера, с глубиной истории и столбцами CSV по умолчанию. Показ имён вместо адресов выключается (`ResolveAddresses = 0`): иначе Process Monitor сам делал бы обратные запросы DNS. В конце ключ возвращается как был. Файл настроек `.pmc` (`/LoadConfig`) больше не используется: его формат не описан, а сохранённый в нём фильтр снова дал бы неполный журнал.
2. **Ключи запуска** (справка `Procmon64.exe /?`): `/NoFilter` — «очистить фильтр при запуске» (вторая гарантия поверх сброса), `/BackingFile capture.pml` — события пишутся в файл, а не в память (память не переполняется и события не отбрасываются), `/WaitForIdle` — дождаться готовности записи. Выгрузка в CSV — `/OpenLog capture.pml /SaveAs capture.csv` тоже с `/NoFilter` и без `/SaveApplyFilter`: в CSV попадают все события журнала.
3. **Пробная запись** (шаг 3, около 20 с) до запуска Rhizomind: Process Monitor с теми же настройками пишет в `procmon-probe.pml`, скрипт запускает тестовый процесс `cmd.exe` (при старте он читает реестр, затем пишет файл `procmon-probe.txt` в папку результатов), запись останавливается, выгружается в `procmon-probe.csv` и проверяется: у тестового процесса должны быть события классов «файлы», «реестр» и «процессы». Если нет — аудит **останавливается сразу** с причиной (например, «в пробном журнале нет ни одного события тестового процесса cmd.exe, хотя событий других процессов 5: Process Monitor отбрасывает события»), Rhizomind не запускается, 85 минут не тратятся впустую. Счётчики пробы — в `results.md`.
4. **Через 60 с после запуска Rhizomind** (шаг 4) скрипт проверяет, что Process Monitor продолжает запись (процесс жив, `capture.pml` растёт); если окно Process Monitor закрыто — аудит останавливается.

Почему проверка событий — на пробной записи, а не на основной: прочитать журнал идущей записи нельзя — `/Terminate` останавливает все экземпляры Process Monitor, а второй экземпляр открытый журнал не выгрузит. Пробная запись идёт тем же Process Monitor с теми же настройками и ключами, что и основная, поэтому то, что отбрасывало события в первом аудите, она поймает. Окончательно полноту проверяет шаг 10 (ниже).

## Если итог «не доказано»

На шаге 10 скрипт пишет в `results.md`, какие классы событий есть в журнале (счётчики по столбцу Operation: файлы, реестр, процессы, сеть, профилирование — у всех процессов и у корневого `rhizomind.exe`) и сколько событий на путях `TokenBroker\Cache` и `ConsentStore` (контроль: к ним обращаются Windows и WAM; в полном журнале за час они есть). Итог «**не доказано**» объясняется конкретно, например: «нет ни одного события корневого процесса Rhizomind (PID 19544)», «нет событий реестра ни у одного процесса (класс Registry выключен?)», «журнал не выгружен в CSV». Журнал считается полным, только если в нём есть события корневого процесса и все четыре класса — файлы, реестр, процессы, сеть.

Что делать: закрыть все окна Process Monitor; запускать PowerShell от администратора; взять свежий Process Monitor с сайта Microsoft Sysinternals; если стоит антивирус или EDR — он может мешать драйверу Process Monitor. Затем повторить аудит. Пробные файлы `procmon-probe.*` не пересылайте (в них события машины за 20 с) — достаточно `results.md`.

## Повторный разбор готового CSV (без нового аудита)

Если разбор нужно пересобрать (новая версия скрипта, другой номер процесса), аудит не повторяют — скрипт разбирает готовый `capture.csv`:
```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\network-audit.ps1" -AnalyzeOnly -Csv "C:\rhizomind-audit-2026-11-01-1922\capture.csv" -RootPid 19544
```
- `-RootPid` — номер процесса `rhizomind.exe` в том запуске. Его видно в `results.md` того аудита, в командной строке движка (шаг 4): в имени канала `--mojo-named-platform-channel-pipe=19544.20112.…` число до первой точки — номер процесса Rhizomind, который запустил движок. Если `-RootPid` не указан, скрипт сам берёт его оттуда из `results.md`, лежащего рядом с CSV.
- Папки хранилищ — из `vaults.json` этой машины и ключа `-Vault "C:\Аудит"` (можно несколько через запятую); временная папка движка — из командной строки движка в самом журнале.
- Итог — в подпапке `reanalysis-<дата>` рядом с CSV (`results.md` и `summary-*.csv`); исходный `results.md` не меняется. Прав администратора и Process Monitor не нужно; разбор большого CSV — минуты на миллион строк.
- Режим проверяет только журнал Process Monitor. Флаги движка, выход, `TokenBroker`, WER и журнал DNS остаются в `results.md` исходного аудита. Если журнал неполный (как в первом аудите), повторный разбор скажет «не доказано» с причиной — недостающие события из него не появятся.

## Что считать нормой, а что нарушением

| Наблюдение | Оценка |
|---|---|
| Любое TCP-соединение, UDP-отправка или запрос DNS **процесса `rhizomind.exe`** | **нарушение** (инвариант 1). Исключение одно — хранилище на сетевой папке: тогда файлы читает и пишет ОС по SMB от имени процесса `System`, а не Rhizomind; для аудита берите хранилище на локальном диске |
| Любое сетевое событие **`msedgewebview2.exe` из дерева Rhizomind** (к Microsoft или куда угодно) | **нарушение гарантии «флаги гасят фоновую сеть»**: записать адрес, этап и время; флаг, отвечающий за эту службу, снимается с гарантий (таблица ниже), находка — в ADR 0007 и `SECURITY.md` |
| Открытый UDP-порт у процесса движка без отправок | записать; само по себе не обращение в сеть (Chromium держит порты служб обнаружения), разбирается по журналу Process Monitor — были ли `UDP Send` |
| Обращения **служб Windows** (`svchost.exe`, `wlidsvc`, `DiagTrack`, `CryptSvc`, `MsMpEng.exe`, `System`) к адресам Microsoft за время аудита | **норма, если** категория есть в `SECURITY.md`, «Ожидаемые обращения к Microsoft»: обязательная диагностика Windows и WebView2, проверка сертификатов, служба входа (`wlidsvc`, решение 64 — при выходе программы не должна появляться), обновления Windows/Defender. Иначе — записать и разобрать: это может быть фон машины, а не следствие запуска Rhizomind |
| Сеть браузера или почтовой программы после «Открыть в браузере» | **норма**: действие пользователя после подтверждения |
| Браузер открылся после «Отмена» или по ссылке `file:` | **нарушение** (С3.7, инвариант 1) |
| Запись файла процессом Rhizomind вне хранилища, `%TEMP%\rhizomind-webview-*` и `%LOCALAPPDATA%\Rhizomind\` | **норма, только если** место есть в `SECURITY.md`, «Записи вне хранилища» (скрипт помечает учтённые: корзина ОС `C:\$Recycle.Bin\…` при удалении заметки, окно выбора папки и др.); иначе — **нарушение** инварианта 2(б) |
| Новый или изменённый файл в `%LOCALAPPDATA%\Microsoft\TokenBroker\Cache\` после выхода | **нарушение** меры решения 64 (кроме файла фонового задания Windows `01c5cb21….tbres`) |
| Запись реестра процессом Rhizomind в ключ без пометки «учтено» | разобрать: если в ключе или значении есть путь хранилища, имя или текст заметки — **нарушение**; иначе — дописать в `SECURITY.md` или найти, что это фон оболочки Windows |
| Временная папка движка осталась после выхода; процессы Rhizomind живы через 30 с | **нарушение** (ADR 0007) |
| Красные подчёркивания слов на шаге 7, файлы `*.bdic` или папка `Dictionaries` во временной папке движка или в журнале (`summary-dictionaries.csv`) | **нарушение** решения задачи 3.3а: проверка орфографии должна быть выключена во всех полях — иначе движок может скачивать словари Hunspell |
| Новый отчёт WER в очереди | **нарушение** инварианта 3, если отчёт про `rhizomind.exe` или `msedgewebview2.exe` |
| В контекстном меню движка есть «Поделиться», «Печать», «Сохранить как», «Веб-снимок» и т. п. | не сеть сама по себе, но канал вывода данных мимо описанных мер — передать оркестратору (аудит 0.1, Р4) |

## Как подтверждается каждый флаг против фоновой сети

Для WebView2 эти флаги не документированы (документирован только `--no-proxy-server`). Отдельно включить и выключить флаг в выпускной сборке нельзя — переменные `WEBVIEW2_*` приложение удаляет, а политика `AdditionalBrowserArguments` умеет только добавлять. Поэтому флаг подтверждается тремя фактами:

1. **Флаг дошёл до движка** — шаг 4 (командная строка процесса браузера).
2. **Нет обращений той службы, которую он выключает,** от процессов движка Rhizomind — шаги 5–9 (опрос соединений, Process Monitor, журнал DNS).
3. **Контроль: на этой машине и этой версии WebView2 такие обращения вообще бывают.** Без контроля «нет обращений» может означать, что служба просто не сработала за время аудита. Контроль — любое другое приложение на WebView2 без наших флагов (новый Outlook, новый Teams, виджеты Windows), запущенное после аудита при работающем Process Monitor: если его `msedgewebview2.exe` обращается к адресам службы, а наш — нет при тех же условиях, флаг подтверждён (в `summary-network-all.csv` такие строки помечены «WebView2 другого приложения — контроль для флагов»). Для `--host-resolver-rules` контроль проще: на шаге 8 браузер, открытый по ссылке, делает запросы DNS — значит журнал DNS их видит, а у процессов движка Rhizomind их нет.

Версия WebView2: в `SECURITY.md` записано, что флаги доходят до процесса браузера на WebView2 155 (так было в CI на момент проверки). На второй машине версия может быть новее (у владельца — 156): шаг 4 подтверждает доставку флагов для этой версии, версия записывается в `results.md`, и итог аудита относится к ней.

| Флаг | Что выключает | Признак в журнале (адреса — ориентиры, проверить по факту) | Подтверждён, если |
|---|---|---|---|
| `--no-proxy-server` | поиск прокси (WPAD) | запросы `wpad`, обращения к прокси-серверу | нет запросов `wpad` от процессов движка (документирован Microsoft — подтверждается тем же наблюдением) |
| `--disable-background-networking` | фоновые службы: конфигурация и эксперименты (вариации), предзагрузки, проверки | `config.edge.skype.com`, `*.ecs.office.com`, иные `*.microsoft.com` от `msedgewebview2.exe` | за 10 минут простоя и сценарий нет обращений; контроль показывает такие обращения у чужого WebView2 |
| `--disable-component-update` | обновление компонентов движка | `edge.microsoft.com`, `msedge.api.cdp.microsoft.com`, `*.tlu.dl.delivery.mp.microsoft.com` | то же |
| `--disable-domain-reliability` | отчёты о сетевых ошибках | загрузки отчётов (`*domainreliability*`, `beacons*`) | то же; без контроля — «не опровергнут», гарантией не считается |
| `--no-pings` | `<a ping>` — оповещение сайта о переходе | — | в интерфейсе Rhizomind нет элементов `<a>`, переходы запрещены — **проверить нечего**: флаг остаётся как запас, гарантией не называется |
| `--host-resolver-rules="MAP * ~NOTFOUND"` | любые запросы имён из движка | события DNS с номером процесса движка; `UDP Send` на порт 53 от `msedgewebview2.exe` в Process Monitor | ноль запросов DNS от процессов движка по **обоим** источникам: журнал DNS (нужен администратор) и отсутствие `UDP Send` на порт 53 у процессов движка в журнале Process Monitor (строка «Запросы DNS … процессов Rhizomind и движка: 0» в `results.md`); при этом браузер по ссылке запросы делает |
| `msSmartScreenProtection` + `IsReputationCheckingRequired = false` | SmartScreen | `*.smartscreen.microsoft.com`, `*.smartscreen-prod.microsoft.com` | нет обращений от процессов движка |

Итог по каждому флагу — одно из трёх: **подтверждён** (три факта), **не опровергнут** (без контроля — в `SECURITY.md` флаг остаётся «защитой в глубину», не гарантией), **опровергнут** (обращение было — флаг снимается с гарантий, находка — в ADR 0007). Результат действителен для записанной версии WebView2: после её обновления аудит повторяется перед следующим выпуском.

## Без скрипта (если PowerShell-скрипты запрещены)

- **Командная строка движка:** `Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'" | Select ProcessId,ParentProcessId,CommandLine | Format-List` — у процесса без `--type=` должны быть флаги из таблицы и не должно быть `--remote-debugging-port`.
- **Соединения:** `Get-NetTCPConnection | Where-Object OwningProcess -in (Get-Process rhizomind,msedgewebview2).Id` или `netstat -b -n` (от администратора) — повторять во время сценария; «Монитор ресурсов» → вкладка «Сеть» → галочки у `rhizomind.exe` и `msedgewebview2.exe`.
- **Process Monitor вручную:** Filter → `Process Name is rhizomind.exe` → Include, `Process Name is msedgewebview2.exe` → Include (затем по столбцу «Parent PID» оставить только дерево Rhizomind; Tools → Process Tree показывает дерево). Сеть: кнопка «Show Network Activity», остальные выключить. Файлы: `Operation is WriteFile`, `Operation is SetRenameInformationFile`; реестр: `Operation is RegSetValue`.
- **Wireshark (необязательно):** захват на основном интерфейсе с фильтром `dns or tcp.flags.syn==1`; процесс по пакету Wireshark не показывает — сопоставлять по времени с действиями и с Process Monitor. Полезен как независимое подтверждение «во время простоя Rhizomind машина не отправляла ничего нового».
- **Корзина на диске C: с отключённой корзиной** (вопрос из «Известных ограничений» `SECURITY.md`): свойства корзины → «Уничтожать файлы сразу», удалить заметку в Rhizomind — должно появиться предупреждение Windows о безвозвратном удалении (библиотека корзины просит его флагом `FOF_WANTNUKEWARNING`); если файл исчез молча — записать.

## Что прислать

`results.md` и `summary-network-app.csv`, `summary-network-all.csv`, `summary-files.csv`, `summary-registry.csv`, `summary-dictionaries.csv` (файлы с пустыми таблицами не создаются). Файлы `capture.pml` и `capture.csv` **не пересылать** (в них все события машины, имена ваших файлов и пользователя) — удалить после разбора.
