# Ревью безопасности выпуска 0.2

Проверен код `3c81257` от 25.11.2026. Состав зависимостей сравнивался с выпущенной версией `v0.1.0` (`7de1d8a`). Статическая часть проверки выполнена. Остаётся получить журнал Process Monitor со второй Windows-машины и результат теста следов для итоговой выпускной сборки. [Спецификация, разделы 6 и 9](../specs/2026-11-01-release-0.2-svyazi.md) · [план, задача 0.2-8.4](../plans/2026-11-01-release-0.2-plan.md).

## Сравнение зависимостей и поиск сетевого кода

Для обеих версий построено дерево со своим `Cargo.lock` и своей копией `vendor/wry`. Команда на Windows для каждой из целей таблицы: `cargo tree --manifest-path src-tauri/Cargo.toml --locked --offline --target <цель> -e normal,no-proc-macro --prefix depth --format "{p}|{f}"`. Сопоставлены имена пакетов, пары имени и версии, активированные функции каждого имени и связи между именами родителя и потомка. Сравнение охватывает зависимости, попадающие в приложение. [Правила проверки](../../tools/check-cargo-tree/tree.ts).

| Цель | Имен в 0.1 | Имен в 0.2 | Добавлено / удалено имён |
|---|---:|---:|---:|
| x86_64-pc-windows-msvc | 168 | 168 | 0 / 0 |
| aarch64-pc-windows-msvc | 168 | 168 | 0 / 0 |
| x86_64-apple-darwin | 172 | 172 | 0 / 0 |
| aarch64-apple-darwin | 172 | 172 | 0 / 0 |
| x86_64-unknown-linux-gnu | 196 | 196 | 0 / 0 |

Различия одинаковы на пяти целях. У приложения появилась прямая зависимость от уже поставлявшегося `getrandom 0.4.3` для знаков планов. Изменились версии `cookie 0.18.2 → 0.18.3`, `url 2.5.8 → 2.5.9` и требуемого им `form_urlencoded 1.2.2 → 1.2.3`. Набор функций по каждому имени сохранился. [Cargo.lock](../../Cargo.lock) · [реестр прямых зависимостей](../dependencies.md).

- `npm run check:deny` прошёл для приложения и `gen-vault`. Обе проверки вернули `advisories ok, bans ok, licenses ok, sources ok`. Для отдельного проекта `wry-probe` проверка `cargo deny --frozen … check advisories` также вернула `advisories ok`.
- `npm run check:cargo-tree` прошёл для пяти целей. Запрещённых сетевых крейтов и крейтов только для тестов в составе приложения и сборки не найдено. [Эталон проекта](../../tools/check-cargo-tree/crates.json).
- На `3c81257` оркестратор выполнил `npm run check:network` после двух сборок Vite. Сетевой код не найден в `src`, `src-isolation` и `dist`, сработали 9 прежних исключений. По сравнению с тегом 0.1 файлы правил сетевой проверки, её список исключений, правила `cargo-deny` и эталон целевых графов совпадают. [Список исключений](../../tools/check-no-network/allowlist.json) · [правила Rust](../../src-tauri/deny.toml).

## Следы на Windows и приёмка

**С2-9 п. 8.** Выпускной сценарий собирает индекс с нуля, переименовывает заметки в приложении и в Проводнике, фиксирует пути служебных файлов, ищет маркеры данных в профиле и реестре. При нормальном выходе проверяет сохранённый индекс, удаление журнала и пустую временную папку. В QA задачи 8.1 зафиксирован успешный Windows CI для `4e2fe5a` (запуск `41651288061`): новых внешних записей 0, учтённых 1. Этот результат относится к указанной сборке. [Сценарий следов](../../tests/e2e/traces.test.ts) · [условия запуска в CI](../../.github/workflows/ci.yml) · [отчёт 8.1](../reviews/release-0.2.md).

Открыты повтор теста следов на итоговой сборке и ручной аудит на втором Windows-компьютере. Для ручного протокола нужны идентификатор сборки, два наблюдаемых пути назначения, результат проверки маркеров и внешних записей, состояние журнала и временной папки после выхода. Скрипт отдельно проверяет полноту захвата. [Сценарий для владельца](network-audit.md#проверка-индекса-и-журнала-выпуска-02).

**С2-9 п. 9.** Разделы модели, ссылки на реализацию и обе проверки зависимостей и сетевого кода сверены на `3c81257`. Статическая часть принята. Для отметки о выполнении всей проверки выпуска нужен результат п. 8.

Проверка относительных Markdown-ссылок (путь на диске и заголовок для ссылок с якорем) прошла для 38 ссылок этого отчёта, 477 в модели безопасности, 8 в инструкции ручного аудита и одной в журнале изменений. Примеры ссылок внутри блоков кода исключены.
