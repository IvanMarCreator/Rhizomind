# Архитектура Rhizomind

**Статус: проектируется.** Что строим и в каком порядке — в [product/requirements.md](product/requirements.md). Решения оформляются как ADR в [adr/](adr/), спецификации выпусков — в [specs/](specs/), планы — в [plans/](plans/). Этот файл — краткий обзор и список решений.

## Сквозные принципы

Следуют из требований и плана выпусков; действуют с выпуска 0.1.

- **Три процесса Electron с узкими границами.** Ядро (main) работает с файлами; интерфейс (renderer) изолирован и не видит Node.js, файловую систему и сеть; мост (preload) выставляет только API ядра.
- **API ядра узкий и версионированный.** Интерфейс вызывает фиксированный набор действий над открытым хранилищем. Позже эта граница станет API плагинов Community.
- **Контур хранилища проверяется в ядре.** Каждый путь сверяется с корнем хранилища до обращения к диску.
- **Файлы — источник правды.** Индекс и раскладка вычисляются и пересобираются; потеря `.rhizomind/` не теряет заметок.
- **Слежение за папкой с 0.1.** Дерево, открытая заметка, а с 0.2 и индекс обновляются по уведомлениям ОС. Запись заметки сверяется с состоянием файла на диске, чтобы не затереть внешнее изменение.
- **Задел под позднее.** Тексты интерфейса через словарь, цвета через переменные темы, окно строится на модели раскладки с 0.1 — чтобы английский язык, свои темы и панели в 0.4–0.5 не требовали переделки.

## Прототип в `src/`

До сбора требований был написан прототип: открытие папки, список заметок, текстовый редактор, вики-ссылки и обратные ссылки, сетевой выключатель, защита путей, протокол `app://`, preload с узким API. Он проверяет идеи, но не является основой. Спецификация выпуска 0.1 решает, что из него взять, а что переписать.

Идеи прототипа, которые соответствуют требованиям и стоит рассмотреть в спецификации 0.1:
- интерфейс загружается через собственный протокол `app://`, без доступа к `file://`;
- все сетевые запросы интерфейса отменяются на уровне сессии; CSP `connect-src 'none'`;
- проверка исходников на сетевой код перед сборкой (`scripts/check-no-network.mjs`);
- узкий версионированный API между интерфейсом и ядром;
- Electron Fuses в конфигурации сборки.

Чего в прототипе нет и что потребуется в 0.1: живой предпросмотр, слежение за папкой и защита от затирания, операции с файлами в дереве, список хранилищ в профиле ОС, сессия Chromium только в памяти, отключение дампов падений, словарь интерфейса, переменные темы.
