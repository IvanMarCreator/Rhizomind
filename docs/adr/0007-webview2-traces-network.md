# ADR 0007. Следы и сеть WebView2

Статус: принято 24.10.2026. Заменяет прежнюю редакцию (служебные данные браузерного движка Electron во временной папке). Уточняет инварианты 1–3.
Основания: ADR 0008, [исследование безопасности Tauri 2 и WebView2](../research/2026-10-24-tauri-webview2-security.md).

## Контекст
Интерфейс работает в системном WebView2 (движок Microsoft Edge на основе Chromium). WebView2 при каждом запуске создаёт папку данных (`Local State`, кэш шейдеров, Crashpad), и выключить это нельзя. По умолчанию Tauri кладёт её в `%LOCALAPPDATA%\<identifier>\` — это нарушает инвариант 2. Часть сетевых функций WebView2 включена по умолчанию (SmartScreen, отправка отчётов о падениях в Microsoft, автозаполнение).

Требования: вне хранилища в профиле ОС — один файл приложения; движок ничего не сохраняет; сетевых обращений нет или они описаны и закрываются политиками.

## Решение

### Папка данных и сессия
- Главное окно создаётся **в Rust** (`WebviewWindowBuilder`), а не из `tauri.conf.json`: только так задаётся абсолютный путь папки данных.
- `incognito(true)` — режим InPrivate: кэш, cookies и хранилища страницы только в памяти.
- `data_directory(<временная папка ОС>\rhizomind-<случайное>)` — уникальное имя на каждый запуск. InPrivate сам по себе папку не убирает, поэтому нужны оба шага.
- **Удаление при выходе:** папку нельзя удалить, пока жив процесс браузера. Ядро запоминает `BrowserProcessId`, после закрытия окон ждёт завершения этого процесса и его дочерних и удаляет папку.
- **Уборка при запуске:** папки `rhizomind-*` во временной папке, чьи владельцы-процессы не живы, удаляются (остатки после аварийного завершения).
- **Переменные `WEBVIEW2_*`** (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, `WEBVIEW2_USER_DATA_FOLDER`, `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` и др.) удаляются из окружения процесса при запуске, до создания окна: они могли бы переопределить папку данных, флаги и сам движок. Ключи реестра политик WebView2 приложение не трогает — это инструмент службы ИТ (см. «Что неустранимо»).

### Флаги движка
- `additional_browser_args` **заменяют** набор wry по умолчанию, поэтому строка собирается так: набор wry (`--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`) + `--no-proxy-server` (нет поиска прокси WPAD; флаг документирован для WebView2).
- К ним добавляются флаги Chromium против фоновой сети: `--host-resolver-rules="MAP * ~NOTFOUND"`, `--disable-background-networking`, `--disable-component-update`. Для WebView2 они не документированы, поэтому **действие каждого подтверждается сетевым аудитом** (Process Monitor и сетевой монитор на чистой Windows); флаг без подтверждённого действия в `SECURITY.md` гарантией не называется.
- Аппаратное ускорение не отключается: оно нужно графу (0.4).

### Сетевые функции WebView2
- **SmartScreen** выключен: `IsReputationCheckingRequired = false` через `with_webview` (и флаг `msSmartScreenProtection` из набора wry).
- **Автозаполнение** выключено в настройках окна (в Tauri по умолчанию включено).
- **Инструменты разработчика** выключены в выпускной сборке: функция `devtools` крейта `tauri` запрещена в `cargo-deny` (ADR 0009).
- **Отчёты о падениях:** по умолчанию WebView2 отправляет дамп в Microsoft (`IsCustomCrashReportingEnabled = false`); wry это свойство не выставляет, Tauri не открывает. Держим свою правку wry: `IsCustomCrashReportingEnabled = true` — дампы не уходят в Microsoft. Правка подключается через `[patch.crates-io]` в `src-tauri/Cargo.toml` на свою копию wry той же версии; исправление предлагаем авторам wry, после принятия патч убираем. Своего обработчика падений нет, дампы не собираем.
- **Проверка орфографии:** CodeMirror ставит `spellcheck="false"`; отсутствие загрузки словарей подтверждается аудитом.

### Режим поставки WebView2 — системная версия (Evergreen)
**Решение владельца:** используем системную версию WebView2 (Evergreen) — сборка лёгкая (установщик около 10 МБ) и быстрая. Движок обновляют Microsoft или служба ИТ. Риск обращений движка к Microsoft оценён владельцем как умеренный, не критичный.

**Режим установщика** (`webviewInstallMode`): предлагается **`skip`** — **на подтверждение владельцу.**

| Режим | Сеть при установке | Если WebView2 нет | Оценка |
|---|---|---|---|
| `downloadBootstrapper` (по умолчанию в Tauri) | только если WebView2 нет: установщик скачивает его с серверов Microsoft | ставится автоматически | в установщике есть загрузчик — лишний вопрос от ИБ |
| `embedBootstrapper` | то же, +1,8 МБ | ставится автоматически | без преимуществ для нас |
| **`skip`** (предлагается) | нет никогда | приложение не запустится; WebView2 ставит служба ИТ офлайн-установщиком Microsoft | установщик не содержит сетевого кода; WebView2 есть в Windows 11 и почти на всех Windows 10 (на нём работают новые Outlook и Teams) |

Почему `skip`: установщик, который при отсутствии компонента идёт в интернет, труднее объяснить ИБ, чем требование «WebView2 Runtime должен быть установлен»; на рабочих машинах он почти всегда уже есть. Если владелец выберет режим по умолчанию, меняется одна строка конфигурации и строка в `SECURITY.md`.

### Что неустранимо приложением и чем закрывается
- **Обязательные диагностические данные WebView2** отправляются в Microsoft всегда; необязательные — по настройке Windows. Отключить на уровне приложения нельзя: это компонент Windows. Закрывается настройками диагностики Windows и политиками службы ИТ.
- **Experimentation and Configuration Service:** WebView2 получает конфигурацию (на неуправляемом ПК — и эксперименты) с серверов Microsoft. Полностью отключает только политика Windows `ExperimentationAndConfigurationServiceControl = 0` — её выставляет служба ИТ.
- Эти обращения делает компонент Windows, а не код Rhizomind; содержимое заметок в них не передаётся. `SECURITY.md` описывает их честно и перечисляет политики для ИТ.

### От обращений к Microsoft можно отказаться — ценой недостатков
Если поставлять с приложением **встроенную фиксированную версию** WebView2 (свой движок в папке приложения), служба ИТ может поставить на путь этого движка правило брандмауэра Windows «запретить исходящие», не задевая Teams и Outlook. Тогда ни приложение, ни его движок в сеть не выходят. Недостатки:
- установщик больше примерно на 180 МБ;
- обновления движка на нас: каждое обновление WebView2 — новый выпуск Rhizomind и, вероятно, повторное согласование с ИБ;
- на Windows 10 при установке нужны права на папку движка (`icacls`);
- с сетевого диска не запускается.

Этот вариант не разрабатывается и не проверяется. К нему вернёмся, только если ИБ отклонит выпуск из-за обращений WebView2 к Microsoft.

### macOS и Linux
`incognito(true)` даёт неперсистентное хранилище (macOS — `nonPersistentDataStore`, Linux — эфемерный контекст). В WKWebView проверка мошеннических сайтов включена по умолчанию; записи в `~/Library/Caches` и `~/.cache` не изучены. Всё это **проверяется при переходе на эти ОС**.

## Последствия
- `SECURITY.md` описывает временную папку (что в ней лежит, что содержимого заметок там нет), правку wry и обращения Evergreen WebView2 к Microsoft вместе с политиками для ИТ.
- Проверка — Process Monitor и сетевой монитор на чистой Windows в критериях приёмки каждого выпуска, с учётом процессов `msedgewebview2.exe`, запущенных приложением.
- Своя копия wry: при каждом обновлении Tauri правка переносится на новую версию wry, пока авторы её не примут.

## Отклонено
- Папка данных в `%LOCALAPPDATA%` (по умолчанию в Tauri): нарушает инвариант 2.
- Папка данных в `.rhizomind/`: технический мусор в хранилище и копия на каждое хранилище.
- Встроенная фиксированная версия: +180 МБ, обновления движка на нас, права на Windows 10, не запускается с сетевого диска; к ней вернёмся, только если ИБ отклонит выпуск из-за обращений WebView2.
- Прежняя редакция для Electron: неприменима после ADR 0008.
