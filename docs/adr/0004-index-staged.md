# ADR 0004. Индекс: поэтапно, JSON → SQLite

Статус: принято 24.10.2026.

## Контекст
Индекс (заголовки, теги, ссылки) лежит в `.rhizomind/` и всегда пересобирается из файлов. Полнотекстовый поиск нужен в 0.3. Объём до 50 000 заметок.

## Решение
- 0.1: индекса на диске нет; список файлов хранится в памяти.
- 0.2: индекс — файл JSON в `.rhizomind/`, целиком в памяти; при запуске сверка с файлами по дате изменения и размеру.
- 0.3: SQLite с полнотекстовым поиском FTS5 (предварительно `better-sqlite3`); выбор движка подтверждается замером в спецификации 0.3.

## Почему
Каждый шаг маленький и проверяемый; индекс производный, поэтому смена формата дешёвая.

## Последствия
Доступ к индексу только через интерфейс модуля индекса, чтобы смена формата не задела остальной код.

## Отклонено
SQLite сразу с 0.2: сложность раньше, чем нужна. Только память навсегда: 150–500 МБ на 50 000 заметок при поиске (оценка).

## Уточнение после ADR 0008 (24.10.2026)
Ядро на Rust, поэтому `better-sqlite3` заменяется крейтом:
- 0.3: `rusqlite` 0.41 с функцией `bundled` (SQLite 3.54, FTS5 включён). Одна база `.rhizomind/index.db` для ссылок и поиска.
- SQLite по умолчанию пишет временные файлы во временную папку ОС — это нарушило бы инвариант 2. Поэтому сборка с `-DSQLITE_TEMP_STORE=3 -DSQLITE_OMIT_LOAD_EXTENSION` (временные данные только в памяти, загрузка расширений невозможна) и при открытии базы `PRAGMA temp_store=MEMORY`. Проверка — Process Monitor.
- Русский стемминг для FTS5 — крейт `frostem` (BSD-3-Clause). Запасной движок поиска — `tantivy`.
- Выбор по-прежнему подтверждается замером в спецификации 0.3.
