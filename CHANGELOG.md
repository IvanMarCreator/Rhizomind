# Изменения

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — `0.МИНОР.ПАТЧ` до 1.0.

## [Не выпущено]

### Добавлено
- Внешние ссылки (задача 1.5, `src-tauri/src/external_links/`): команда `open_external` открывает только `http`, `https`, `mailto` и только после подтверждения в системном окне ядра «Rhizomind — внешняя ссылка» (кнопки «Открыть в браузере» — по умолчанию — и «Отмена»), модальном к окну заметки. В окне — ровно та строка, которая уйдёт в ОС (нормализация крейтом `url`, домен в Unicode вместе с punycode). Отклоняются другие схемы, скрытые форматирующие символы, адреса длиннее 8 КБ, вложения `attach` в `mailto`, логин и пароль в `http(s)`; одно окно подтверждения на окно приложения. Передача ОС — крейт `open` 5.4.5. Новые зависимости: `url` 2.5.8 (уже был в дереве), `open` 5.4.5.
- Оболочка окна по концепту К2 с акцентом индиго (задача 2.2, `src/shell/`): лента иконок («Файлы» прячет и показывает боковую панель, «Быстрый переход», внизу «Настройки»), боковая панель с местом под дерево файлов и заготовкой переключателя хранилищ, строка над заметкой (назад/вперёд, путь и имя, переключатель «книга/карандаш»), пустое состояние «Нет открытой заметки», уведомления внизу окна. Заголовок окна пока системный.
- Запуск окна: сверка версии API; при несовпадении или отказе моста — понятное сообщение из словаря вместо пустого окна. Тема и режим редактора — из настроек хранилища, открытая заметка — из раскладки; ошибки чтения не мешают открыть окно и показываются уведомлением. Текст ошибки для пользователя — только из словаря, без `IpcFailure.detail` и текста исключений (`src/i18n/errors.ts`).
- Модель раскладки v1 (`src/core/layout/`): дерево разбиений и панелей с вкладками, JSON с форматом и версией для `workspace_write` (не больше 1 МБ), повреждённая раскладка заменяется раскладкой по умолчанию с уведомлением.
- История переходов (`src/core/history/`): назад/вперёд кнопками и Alt+← / Alt+→, переименование и удаление путей в истории, предел 100 шагов.
- Словарь `ru` (`src/i18n/`): все тексты интерфейса, `errors.<код>` и `names.<причина>` для всех ошибок ядра; тест полноты ищет тексты мимо словаря в разметке `.svelte` и строках кода.
- Темы (`src/theme/`): все 30 цветов из `docs/design/tokens.md` как CSS-переменные светлой и тёмной темы, режимы «Как в системе / Светлая / Тёмная» со слежением за системой. Шрифты Inter 4.1 и JetBrains Mono 2.304 встроены файлами (OFL 1.1), иконки Lucide 1.61.0 — контурами SVG (ISC).
- Компонентные тесты на Vitest + Testing Library для Svelte + jsdom (проект `components`); сценарный тест оболочки со снимками экрана в светлой и тёмной теме (`tests/e2e/shell.test.ts`); снимки проверяются на пустоту.

- Генератор тестового хранилища `tools/gen-vault` (задача 1.6): `cargo run -p gen-vault -- --notes N --out <папка> [--seed S] [--big-mb M] [--manifest <файл>]` — вложенные папки, русские и английские имена, вики-ссылки всех видов, неразрешённые ссылки, дубликаты имён, код с `[[...]]`, PNG, PDF, TXT, CSV, ZIP, скрытые файл и папка, имя с `#`, образцы LF/CRLF/BOM и невалидного UTF-8, файл больше лимита (`--big-mb`, до 1024 МБ, пишется потоком); у первой заметки каждой группы дубликатов дата создания строго меньше; одинаковое зерно — байт в байт одинаковое хранилище; манифест в JSON для тестов ядра. `cargo test -p gen-vault` проверяет состав; 10 000 заметок в CI — до 5 секунд на Windows и до 2 секунд на Linux.
- Доработка контракта API v1 по ревью (задача 0.4.1): пределы параметров в слое команд (`commands/limits.rs`, снимок `limits.snap`, `src/api/limits.ts`); все варианты перечислений в снимке `enums.snap` с исчерпывающей проверкой в TypeScript; `name_check` с полем `renaming` (смена только регистра разрешена); переименование не меняет расширение заметки (`note_extension`); `note_write` без `format` — BOM и переносы ядро берёт из файла, неизменённый текст не пишется; `vault_current` без пути к папке; вид элемента `attachment` вместо `file`; `links_resolve` отдаёт `null` для плохих целей; тип настроек на диске отдельно от контракта; интерфейс слушает события своего окна; `tauri-plugin-dialog` 2.8.3 для диалогов ядра (без прав интерфейсу); тесты отказов прав Tauri и плагинов и вызова со стороннего адреса.
- Контракт команд ядра API v1 (задача 0.4): 23 команды и 5 событий из спецификации 0.1 (С5.5) с типами запросов, ответов и ошибок (`src-tauri/src/commands/`). Ошибка — машинный код и ключ словаря `errors.<код>`; путь в хранилище — массив компонентов; версия файла — хэш, размер, дата изменения. Команды вызывают интерфейсы модулей ядра `registry`, `vault`, `names`, `links`, `switcher`, `watcher`, `external_links`; модули пока — заглушки с ошибкой `not_implemented`. `vault_current` уже отвечает: `api_version` = 1 и хранилище окна.
- Права своих команд: единый список `src-tauri/src/commands/list.rs` для `AppManifest::commands` и `generate_handler!`; главному окну выданы права на эти команды и на подписку на события (`core:event:allow-listen`, `allow-unlisten`). Тесты на настоящей конфигурации прав: команда вне списка отклоняется, даже если обработчик есть.
- Снимки контракта `contracts/v1/*.snap`: их пишет `cargo test` (insta) и проверяет Vitest — расхождение типов Rust и TypeScript валит тест.
- `src/api/`: типы TypeScript, обёртки по каждой команде и событию, подмена ядра для тестов (`testing.ts`), проверка версии API при запуске.
- Каркас приложения на Tauri 2.12.5 (задача 0.2): ядро на Rust 1.99.1 (`rust-toolchain.toml`), главное окно создаётся в ядре; интерфейс на Svelte 5 + Vite 8 + TypeScript strict показывает заголовок «Rhizomind» на фоне светлой или тёмной темы; `src/api/` — обёртка над вызовами ядра.
- Безопасность каркаса: CSP без внешних хостов, `freezePrototype`, без `window.__TAURI__`, у окна нет прав (capabilities), список своих команд пуст, установщики без загрузки WebView2 (`skip`), NSIS для текущего пользователя.
- Проверки в `npm run verify`: сетевой код интерфейса по синтаксическому дереву (исходники и сборка), лицензии npm с разбором SPDX, `cargo fmt`, `clippy`, `cargo test`, `cargo deny check`, `cargo tree` по пяти десктопным целям без сетевых крейтов.
- Сценарный тест (tauri-driver + WebdriverIO): окно открывается, снимок экрана сохраняется на Windows и Linux. Тест идёт на сборке с функцией `webdriver` (`npm run build:e2e`): WebView2 155 не принимает порт отладки от msedgedriver через переменную окружения, если приложение задаёт свои флаги; выпускные сборки — без этой функции.
- CI: Windows и Linux, actions закреплены по SHA, кэш Rust и npm, снимки экрана и портативная сборка Windows как артефакты; сборки `package:portable`, `package:msi`, `package:nsis`, SBOM (`npm run sbom`).
- `docs/dependencies.md` — перечень зависимостей с лицензиями и ответом про сетевой код.
- Требования и план выпусков Secure-редакции 1.0.
- Архитектурные решения ADR 0001–0007.
- Спецификация выпуска 0.1 «Основа».
- Проверка в GitHub Actions (CI) на Windows и Linux, Node.js 22.
- `.gitattributes`: исходники с LF, тестовые образцы без преобразования концов строк.

### Изменено
- Код интерфейса проверяется отдельным `src/tsconfig.json` без типов Node; тесты и инструменты — корневым `tsconfig.json` (обзор задачи 0.2). Сценарный тест ищет сборку с учётом `CARGO_TARGET_DIR`.
- Рабочее пространство Cargo: корневой `Cargo.toml` (члены `src-tauri`, `tools/gen-vault`), `Cargo.lock` и профиль выпуска перенесены в корень; папка сборки осталась `src-tauri/target` (`.cargo/config.toml`). `vendor/` исключена из рабочего пространства. `npm run verify`: `cargo fmt`, `clippy` и `cargo test` — по пакетам `rhizomind` и `gen-vault`, `cargo deny` — отдельно для приложения и для генератора; `cargo tree` и SBOM — только приложение.
- Документы под Tauri 2 (ADR 0008): ADR 0006 (слежение — `notify` 9) и ADR 0007 (следы и сеть WebView2, системная версия WebView2) приняты в новой редакции; новый ADR 0009 (безопасность границы ядро — интерфейс); уточнение ADR 0004 (`rusqlite`); спецификация 0.1 (ревизия 5) и план 0.1 переписаны и снова на утверждении; `SECURITY.md`, `ARCHITECTURE.md`, `CONTEXT.md`, `README.md` обновлены.
- Прототип перенесён в `prototype/` как справочник; ссылки в документации обновлены.
