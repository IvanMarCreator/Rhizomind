# Изменения

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — `0.МИНОР.ПАТЧ` до 1.0.

## [Не выпущено]

### Добавлено
- Один экземпляр программы (задача 0.5, решения 57, 58, `src-tauri/src/single_instance/`): повторный запуск не открывает второй процесс — Windows: будит первый (мьютекс `Local\Rhizomind.SingleInstance`, окно для сообщений, `WM_COPYDATA`), тот выводит вперёд последнее активное окно; Linux, macOS: файл-замок `instance.lock` рядом с `vaults.json`, второй запуск пишет «Rhizomind уже запущен» и выходит. Проверка — до временной папки WebView2 и чтения списка хранилищ: второй процесс ничего не пишет. Точка `on_second_instance` — для окна «Управление хранилищами» (задача 2.8). Плагин `tauri-plugin-single-instance` не взят: тянет `tokio/net`, `zbus`, `socket2` (исследование `docs/research/2026-10-26-single-instance.md`). Сценарный тест `tests/e2e/single-instance.test.ts` (Windows, Linux; тестовая сборка, свой профиль и имя мьютекса). Ограничения механизма — в `docs/SECURITY.md`, «Известные ограничения».
- Список хранилищ и окна (задача 1.3, `src-tauri/src/registry/`, `src-tauri/src/windows/`): `vaults.json` в `dirs::data_local_dir()/Rhizomind/` (Windows `%LOCALAPPDATA%`, не Roaming — решение 46) — версия формата, имена и пути хранилищ, последнее открытое, размер и положение окна; атомарная запись; испорченный файл копируется в `vaults.broken-<мс>.json`, приложение не падает. Работают `vault_list`, `vault_open`, `vault_remove_from_list`, `vault_create`, `vault_open_folder`: другое хранилище — в новом окне защищённой оболочки, уже открытое — фокус (и при одновременных вызовах); окно без хранилища открывает его в себе. При запуске открывается последнее хранилище с размером и положением его окна (положение — только если окно видно на одном из экранов).
- Метки окон `vault-<16 случайных шестнадцатеричных цифр>`, права окна — по шаблону `vault-*` (`capabilities/main.json`); фильтр изолированного iframe пропускает подписку на события только с целью «окно с меткой» — слушатель `Any` получал бы события чужих окон.
- Тестовая сборка (`webdriver`): `RHIZOMIND_E2E_VAULT` открывает тестовое хранилище без окна выбора папки, `RHIZOMIND_E2E_PROFILE_DIR` — список хранилищ во временной папке; сценарный тест дерева `tests/e2e/tree.test.ts` включён (ввод имени без `setValue`, перетаскивание событиями HTML5).
- Защищённая оболочка WebView2 (задача 0.3): режим InPrivate; папка данных движка во временной папке ОС (`rhizomind-webview-<pid>-<случайное>`), удаление после завершения процесса браузера и уборка остатков прошлых запусков; переменные `WEBVIEW2_*` и `TAURI_WEBVIEW_AUTOMATION` удаляются из окружения до создания окна; флаги движка — набор wry + `--no-proxy-server` + флаги Chromium против фоновой сети (действие подтверждается сетевым аудитом); SmartScreen выключен (`IsReputationCheckingRequired = false`); автозаполнение выключено; запрет переходов на чужие адреса, новых окон, загрузок и всех разрешений браузера; отчёты Windows об ошибках ограничены (`SetErrorMode`, `WerSetFlags`).
- Своя копия wry 0.57.1 (`vendor/wry/`, `[patch.crates-io]` в корневом `Cargo.toml`) с одной правкой: `IsCustomCrashReportingEnabled = true` — дампы падений WebView2 не уходят в Microsoft; текст предложения авторам wry — `docs/upstream/wry-crash-reporting.md`.
- Isolation pattern: вызовы ядра через изолированный iframe с фильтром команд (`src-isolation/`): пропускаются ровно команды API v1 из `src-tauri/src/commands/list.rs` и `listen`/`unlisten`; тест сверяет фильтр со списком.
- Тесты оболочки: сценарные (переход наружу, `window.open`, загрузка, `fetch` наружу, разрешения, isolation), тест следов и флагов на выпускной сборке в CI на Windows, интеграционный тест живого WebView2 (`src-tauri/tests/webview2_runtime.rs`).
- Тестовая сборка `npm run build:e2e` — в отдельной папке `src-tauri/target-e2e`, с пометкой в заголовке окна; `package:portable` её не упаковывает. На Linux она без InPrivate (иначе WebKitWebDriver не открывает сессию), на Windows берёт папку данных и порт `0` от msedgedriver. Сценарные тесты не зависают: предел создания сессии WebDriver 100 с с журналом tauri-driver в `test-results/e2e/`, пределы времени заданий и шагов в CI.
- Доработка 0.3 по ревью безопасности: окно Windows показывается только после того, как движок подтвердил InPrivate (иначе — сообщение «обновите WebView2 Runtime», окно не открывается); код порта отладки компилируется только в тестах и тестовой сборке (в выпускном файле нет `--remote-debugging-port=`); `package:msi` и `package:nsis` отказываются упаковывать тестовую сборку (`build.beforeBundleCommand`); единый вход через учётную запись Windows выключен (значение по умолчанию, тест).
- Известный локальный след (задача 0.3): при закрытии окна в `%LOCALAPPDATA%\Microsoft\Credentials\` появляется файл диспетчера учётных данных Windows; создатель не установлен, расследование отложено (`docs/reviews/2026-10-25-task-0.3.md`). Учтён в `docs/SECURITY.md`, раздел «Записи вне хранилища» (решение 45); тест следов допускает ровно новые файлы в этой папке.
- Слежение (исправление 1.4): файл, который перенесли или удалили между чтением списка папки и открытием для идентификатора, в сверке не участвует (раньше на Windows он уходил как «изменён», а перенос — как «появился»); неизвестный идентификатор при тех же размере и дате правкой не считается. Нагрузочные тесты слежения на Windows стабильны (причины и прогоны — `docs/reviews/2026-10-25-task-1.4.md`); тесты правок ждут, пока придёт правка каждого файла.
- Слежение (исправление 1.4): исчезнувший файл с идентификатором выдаётся «исчез» не сразу, а через 0,6 с, если за это время не появился по новому пути (событие о новом пути переноса может прийти следующей пачкой).
- Слежение (исправление 1.4): своя запись узнаётся по размеру и хэшу самого файла, а не по размеру из списка папки (на Windows он обновляется с запозданием — свои записи изредка уходили как внешние); открытие для хэша повторяется, если файл ненадолго занят. Старые пути переносов читаются без повторного обхода уже прочитанных папок.
- Слежение (исправление 1.4): перенос файла во время обхода (Rescan посреди массового переноса) распознаётся как перенос — пути с одинаковым идентификатором перепроверяются после обхода, а исчезнувшее с идентификатором смотрится второй раз; раньше на Windows часть переносов уходила как «исчез» + «появился».
- Команды ядра на настоящих модулях (задача 1.7): все 23 команды контракта v1 работают с настоящими `vault`, `links`, `switcher`, `external_links`; обращения к диску, диалоги и поиск — в `spawn_blocking`. Каждый путь проверяется по компонентам в слое команд (`invalid_path`), имя нового элемента — с той же причиной, что у `name_check` (имя `.rhizomind` в любом регистре — `reserved_name`). Хранилище открывается одной функцией `Core::open_vault` для `vault_create`, `vault_open_folder`, `vault_open`: зависимости при открытии (`Vault::open_with`), общий журнал своих записей с наблюдателем (`src-tauri/src/own_writes.rs`, ключ пути — `names::key`), наблюдатель за папкой и события только окну этого хранилища (`src-tauri/src/events/`); закрытое окно отвязывается от хранилища. Общий список заметок для ссылок и быстрого перехода обновляется сразу после своей команды и по событиям наблюдателя, идемпотентно. Из пачек наблюдателя выводятся `note:changed` (с версией с диска), `note:renamed` и `note:deleted` для всех заметок по пути и под ним; `note_write` при конфликте отправляет `note:conflict-saved`. Список хранилищ (`vaults.json`) и новые окна — по-прежнему задача 1.3.
- Открытие хранилища не теряет изменения снаружи во время обхода папки; окно, закрытое во время открытия, не получает хранилище и не оставляет наблюдателя. Папка новых заметок в настройках проверяется как путь хранилища и не может быть служебной. Интерфейсу запрещён глобальный `listen` событий (ESLint) — только события своего окна.
- Новое событие `vault:availability` (`{ available }`) — папка хранилища пропала или вернулась; расширение контракта v1 (`contracts/v1/event.vault.availability.snap`, `src/api/types.ts`).
- Общий замок диалогов ядра (`src-tauri/src/dialogs.rs`): подтверждение внешней ссылки, выбор папки хранилища и новое окно подтверждения безвозвратного удаления на диске без корзины — не больше одного на окно.
- Наблюдатель после сбоя получателя сам проходит полную сверку через 2 с, не дожидаясь новых изменений на диске.

- Быстрый переход (задача 2.7, `src/quick-switcher/`, макет Э3): Ctrl+O (и в русской раскладке) или кнопка на ленте открывает окно с полем ввода; нечёткий поиск по именам и путям — командой ядра `switcher_search` (топ-50), совпавшие буквы выделены, одинаковые имена различаются папками справа. Стрелки по кругу, Enter открывает, Esc и клик мимо окна закрывают; Enter во время набора через IME не срабатывает. Если заметки с таким именем нет — последний пункт «Создать заметку „…“»: имя проверяет `name_check`, заметка создаётся `note_create` в папке по настройке «где создавать новые заметки» и открывается; недопустимое имя — пояснение под полем, предупреждение об имени — уведомлением. Запросы без задержки: первый уходит сразу, пока ядро отвечает — копится только последний, ответ на устаревший текст не показывается. Переход из окна — шаг истории (Alt+← / Alt+→ и кнопки назад/вперёд); пока открыто модальное окно (быстрый переход, подтверждение удаления), Ctrl+O и Alt+← / Alt+→ не действуют. Окно, закрытое во время создания, заметку не создаёт (закрыли до `note_create`) и не открывает (закрыли после). Скорость ответа настоящей команды на 10 000 заметок проверяется в задаче 1.7 и в сценарных тестах; здесь — только поиск ядра без команды (`search_10k_names_within_20ms`).
- Быстрый переход, доработка по решениям 50 и 51: Tab подставляет в поле полное имя выбранного пункта (как автодополнение), поиск обновляется, выбор остаётся на той же заметке — по пути, поэтому из одинаковых имён остаётся выбранная; на пункте «Создать заметку» Tab ничего не меняет. Tab и Shift+Tab не уводят фокус из поля, клик внутри окна мимо поля фокус не забирает. В подсказках внизу окна — «Tab дополнить». Запрос с `/` или `\` — пункт создания сразу неактивен с пояснением «Косая черта в имени недопустима: сначала создайте папку»; Enter и клик по нему ничего не делают, ядро не вызывается (`hasFolderSeparator` в `src/quick-switcher/create.ts`).
- Дерево файлов (задача 2.3, `src/tree/`, С3.2, макет К2 вариант 3Б): все папки и файлы хранилища, скрыты `.rhizomind/` и имена с точкой; папки сверху, естественный порядок `Intl.Collator('ru', { numeric: true })`; заметки без `.md`, вложения — без расширения с меткой типа (`PNG`, `PDF`) и не открываются. Кнопки «Новая заметка» и «Новая папка» при наведении на папку, те же действия в контекстном меню (плюс «Переименовать F2», «Удалить Delete»); новая заметка «Без названия» (следующее свободное имя «Без названия 1»…) создаётся, открывается и сразу получает поле имени. Переименование по F2, двойному клику и клику по заголовку заметки над текстом (Э4, Э4б): проверка при вводе командой `name_check`, пояснение или предупреждение (`unlinkable`, `hidden`) под полем из словаря, Enter не срабатывает при ошибке, у файлов правится имя без расширения; новое имя сразу в дереве и в пути над заметкой. Перемещение перетаскиванием (на папку — в неё, на файл — в его папку, на пустое место — в корень). Delete — окно подтверждения по настройке «подтверждение удаления», затем корзина ОС; ответ ядра «удалено безвозвратно» — уведомление, «отменено» — ничего. Обновление по событию `vault:changed`, при `rescan` и при расхождении — перечитать `tree_list`. Клавиши: стрелки, Home/End, Enter, F2, Delete, клавиша меню и Shift+F10. Ctrl+Z (решение владельца 47): в поле имени — обычная отмена набора, затем исходное имя; после переименования (фокус в дереве или на заголовке заметки) — отмена последнего переименования с проверкой `name_check`, если прежнее имя занято или элемента нет — уведомление. Кнопки создания в корне — в заголовке панели «ФАЙЛЫ», видны при наведении на панель и при фокусе (решение 48). Окно закрывает удалённую заметку и следует за переименованием (`WindowModel.entryRenamed/entryRemoved`, `closeNote` в модели раскладки). Сценарный тест `tests/e2e/tree.test.ts` пропущен до задачи 1.7 (окно сценарного теста пока не может открыть хранилище).
- Доработка слежения по ревью 1.4: склейка без кэша идентификаторов `FileIdMap` (он ходил по точкам соединения за пределы хранилища); пропавший или недоступный корень — сигнал «хранилище недоступно» без исчезновений, папка без доступа остаётся в дереве и сверяется повторно; журнал своих записей хранит до 4 последних версий на путь (быстрые автосохранения не дают ложных внешних изменений); совпадение идентификатора файла подтверждается размером и датой на всех ОС, запасной путь — и при разных идентификаторах (FAT/exFAT); новая папка появляется раньше переноса в неё; паника получателя не останавливает наблюдатель. Сигналы наблюдателя — `WatcherEvent` (`Changed`, `Unavailable`, `Available`, `DeliveryFailed`).
- Слежение за папкой хранилища (задача 1.4, ADR 0006): `notify` 9.0.0-rc.6 + `notify-debouncer-full` 0.8.0-rc.2, модель «дерево хранилища» в ядре и пачки изменений `vault:changed` (`created`, `modified`, `removed`, `renamed`, флаг `rescan`). Пути из событий сверяются с диском: новая папка обходится целиком, переименования и перемещения — по идентификатору файла (`file-id`), запасной путь — размер и дата; переполнение буфера ОС (Rescan) и ошибки наблюдателя — полная сверка; `.rhizomind/` и имена с точкой не учитываются. Журнал своих записей `OwnWrites` «путь → (хэш, размер)»: хранилище пишет в него до замены файла, и своя запись не становится внешним изменением. Нагрузочные тесты (`cargo test -p rhizomind --lib watcher::load_tests -- --ignored`) — отдельным шагом CI.
- Внешние ссылки (задача 1.5, `src-tauri/src/external_links/`): команда `open_external` открывает только `http`, `https`, `mailto` и только после подтверждения в системном окне ядра «Rhizomind — внешняя ссылка» (первая кнопка, по умолчанию, — «Открыть в браузере», для `mailto` — «Открыть в почте»; вторая — «Отмена»), модальном к окну заметки на Windows и macOS. В окне — ровно та строка, которая уйдёт в ОС (нормализация крейтом `url`; домен — punycode, Unicode в скобках); в этой строке только символы RFC 3986. Отклоняются другие схемы, скрытые символы, адреса длиннее 8 КБ, вложения и управляющие символы в параметрах `mailto`, логин и пароль в `http(s)`; одно окно подтверждения на окно приложения. Передача ОС: на Windows — `ShellExecuteExW` с классом протокола (без PowerShell и `cmd.exe`), на macOS и Linux — крейт `open` 5.4.5. `clippy.toml` запрещает сетевые методы и типы в нашем коде. Зависимости: `url` 2.5.8, `windows-sys` 0.61.2 (Windows), `open` 5.4.5 (macOS, Linux) — все уже были в дереве или без сетевого кода.
- Хранилище: файлы и контур (задача 1.2, `src-tauri/src/vault/`). Контур: проверка каждого компонента пути (`..`, `.`, `:`, разделители, `\\?\`, зарезервированные имена Windows, точка или пробел в конце, короткие имена 8.3), канонический корень (`dunce`), символические ссылки и точки соединения NTFS в каждом компоненте, итоговый путь по дескриптору (`GetFinalPathNameByHandleW`, `/proc/self/fd`); `.rhizomind/` недоступна обычным командам. Чтение: версия файла (`blake3` + размер + дата), BOM и переносы, только чтение для невалидного UTF-8 и файла больше лимита из настроек. Атомарная запись через `.rhizomind/tmp/` (`ReplaceFileW` на Windows сохраняет дату создания), «байт в байт», конфликт — копия «Имя (внешняя версия ГГГГ-ММ-ДД ЧЧ-ММ).md» до замены, без копии при том же хэше; свои записи регистрируются до замены для наблюдателя. Дерево, заметки с датой создания, создание, проверка имени, переименование (в том числе только регистр), перемещение без затирания, корзина ОС в отдельном потоке; без корзины — безвозвратно только после подтверждения. `settings.json` (версия формата, неизвестное не затирается) и `workspace.json`. - Проверка интерфейса на сетевой код после слияния 0.3 (запрет `form.submit()`) и дерева 2.3: параметр поля имени `submit` переименован в `save` (`src/tree/nameInput.svelte.ts`) — вызов `options.submit(...)` проверка принимала за отправку формы.
- Наблюдатель за хранилищем не остаётся у закрытого окна, если окно закрыли раньше, чем началось открытие хранилища (обзор 1.7): закрытые метки окон помнятся (`Core::unbind_window`).
